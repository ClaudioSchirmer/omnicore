QueryHandler · CQRS

The QueryHandler is the processing unit for a read (GET), symmetric to the CommandHandler on the write side: Request → Query → Handler on the read path mirrors Request → Command → Handler on the write path. The framework's generic FindByParamsQueryHandler / FindByIDQueryHandler implement pipeline.Handler[*Q, R] and resolve the read through the queries.ViewReader port (ReadPage / ReadByID), so the consumer writes no handler code for the common case. Reads come from MongoDB (pre-composed view) and support dynamic filters, cursor pagination, sorting, field projection, and text search — all derived from the query string and the ViewDefinition.

This page covers the QueryHandler concept and the end-to-end flow of a GET. Two canonical wrappers serve the common reads — fwweb.HandleQueryWithParams (paged listing) and fwweb.HandleQueryWithID (by-id lookup) — documented in full, together with the projector contract, the query-string capabilities (allowlist, nested embed groups, ?fields=, ?sort=, keyset pagination with the per-view ?limit= ceiling, ?onlyTotal=true) and the complete wiring example, under Auto query handlers. Routes that need a custom shape opt out of the wrappers — see Custom query handler. The end-to-end layer trace (wrapper → handler → ToCriteria → ViewReader → Mongo → envelope) lives in the Read lifecycle map.

Full flow of a GET

Example: GET /users?email.in=a@x,b@y&sort=-created_at&limit=20&fields=name,email.
