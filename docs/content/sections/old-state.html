Old-state snapshot

Domain owns the “what did the entity look like before this write?” snapshot. The framework's Get* functions capture it automatically; BuildRules consumes it via the typed helper domain.Old[T](e) T; the audit builder consumes it to compute changes (kind=delta) or to emit snapshot (kind=snapshot on Delete). Powers both transition-aware invariants in the domain and timeline reconstruction in audit.

Read the old state inside BuildRules

func (u *User) BuildRules(actionName string, svc domain.Service, r *domain.Rules) {
    r.IfUpdate(func() {
        if old := domain.Old(u); old != nil {
            if old.Email != u.Email && u.Activated {
                r.AddNotification("Email", EmailLockedAfterActivationNotification{})
            }
        }
    })
}

For aggregates, domain.Old(u) also exposes the prior children via the usual helpers (e.g. domain.GetCurrentItemsOf[Address](&domain.Old(u).AggregateRoot)). Use it to express invariants spanning the boundary across the transition.

How the snapshot is captured

  • Update / Patch (closure form): domain.GetUpdatable[T](loaded, apply, svc) and domain.GetPartialUpdatable[T](loaded, apply, svc) snapshot the entity before running the apply closure. The mutation happens inside the domain function — the caller passes cmd.ApplyTo or cmd.ApplyPartiallyTo directly (signature func(T)). Auto handlers do this automatically; manual handlers follow the same pattern.
  • Delete / Archive / Unarchive: domain.GetDeletable / GetArchivable / GetUnarchivable snapshot at function entry (no mutation step in these flows). Old() returns the entity in its pre-transition state — used both in BuildRules (e.g., r.IfDelete rule using the loaded balance) and for audit forensics.
  • Insert: NO snapshot. A freshly created entity has no prior state by definition. Inside BuildRules, domain.Old(u) returns the typed zero value; defensive code with if old != nil guards Update-only rules.

What the clone looks like

The clone is produced via a JSON round-trip (encoding/json) — only exported fields cross. Private BaseEntity/AggregateRoot state (notifCtx, events, signature) is intentionally NOT cloned, so the clone is a read-only “ghost”: calling mutator domain methods on it is a silent no-op because its notifCtx is nil. The aggregate path also deep-copies the items map so Old() reflects the children as they were before mutation.

Audit event shape

The audit pipeline emits flat top-level fields — both as slog attrs on the echo line AND as top-level columns + JSONB payload on the audit_events row — with no nested envelope. The kind field discriminates the body block: snapshot (Insert / Delete), delta (Update / PartialUpdate), transition (Archive / Unarchive). Exactly one body block applies per event.

  "dateTime": "2026-06-09T12:00:00Z",

    { "field": "email", "fieldLabelKey": "UserEmailField", "from": "a@x.com", "to": "b@x.com" }
  ],
  "children": {
    "Address": [
      { "id": "addr-1", "op": "updated",  "changes": [{ "field": "label", "fieldLabelKey": "AddressLabelField", "from": "home", "to": "home renamed" }] },
      { "id": "addr-2", "op": "archived", "snapshot": { "label": "work" } },
      { "id": "",       "op": "inserted", "snapshot": { "label": "vacation" } }
    ]
  }
}

PUT and PATCH share verb: "update" — SQL fingerprint is identical (UPDATE col=val, updated_at=NOW()), so the audit verb is identical. The PUT vs PATCH distinction lives in actionName (GetUpdatable vs GetPartialUpdatable) — same way the domain unifies them via IfUpdate. Unchanged columns never appear in changes — no redundancy with the snapshot.

Aggregate children block

For aggregate roots (entities implementing AggregateRootProvider), the audit builder expands the event with a nested children map keyed by child typeName. Each entry carries {id, op, snapshot} or {id, op, changes} following the same kind discipline as the root event — enough to reconstruct a per-child timeline in ELK without parsing the outbox payload. Granularity stays B: one audit event per write, children nested inside, matching the “aggregate = event unit” semantic of the outbox.

Child op is SQL-grounded — every value echoes the SQL fingerprint of what the persister emitted on the row. Same vocabulary as the root verb, no exceptions. See the Canonical write lifecycle section for the full SQL ↔ op mapping; the table below summarizes the child cascade per root verb.

Custom infra escape hatch

Implementations that bypass the framework's Get* path (raw SQL building an Updatable by hand — not exposed by the public API today, but conceptually) will not have Old() populated. On Update the audit builder's changes degrade to every column with from: null; on Delete it falls back to the live source's snapshot. Graceful degrade, not error.
