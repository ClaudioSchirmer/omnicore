Old-state snapshot

Domain owns the “what did the entity look like before this write?” snapshot. The framework captures it automatically when the entity is born — the moment it finishes hydrating from the system of record; BuildRules consumes it via the typed helper domain.Old[T](e) T; the audit builder consumes it to compute changes (kind=delta) or to emit snapshot (kind=snapshot on Delete). Powers both transition-aware invariants in the domain and timeline reconstruction in audit.

Read the old state inside BuildRules

func (u *User) BuildRules(actionName string, svc domain.Service, r *domain.Rules) {
    r.IfUpdate(func() {
        if old := domain.Old(u); old != nil {
            if old.Email != u.Email && u.Activated {
                r.AddNotification("Email", EmailLockedAfterActivationNotification{})
            }
        }
    })
}

For aggregates, domain.Old(u) also exposes the prior children via the usual helpers (e.g. domain.GetCurrentItemsOf[Address](&domain.Old(u).AggregateRoot)). Use it to express invariants spanning the boundary across the transition.

How the snapshot is captured

One rule, identical for all five state-changing verbs — Update, PartialUpdate, Archive, Unarchive and Delete: the snapshot is taken when the entity is born, and nothing that happens afterwards can replace it. “Born” means the load that hydrated it out of the system of record: the relational loader's single-entity path (FindOne, which every FindByID / FindArchivedByID and every custom repository finder funnels through) stamps it, and the write-side load helpers persistence.LoadForWrite / LoadArchivedForWrite stamp it for a hand-rolled repository that bypasses the loader.

Everything a write does between the load and the verb is therefore excluded from Old() by construction — a Command's ApplyTo, a BuildRules closure such as r.IfArchive that flips a status field, a domain method a manual handler calls. That is the point: Old() is what the database holds, so a rule can compare intent against reality and the auditor can record where the entity came from.

  • Order does not matter to the caller. The update verbs accept an apply closure (domain.GetUpdatable[T](loaded, apply, svc, "GetUpdatable")) and the bodyless verbs do not — but the snapshot no longer depends on that. A mutation applied before the Get* call and one applied inside the closure are equally outside Old().
  • The Get* family is the floor, not the mechanism. If an entity carries no snapshot when a Get* runs — it was assembled in memory and never loaded — the verb captures one there, so Old() is never nil for a state-changing verb. A snapshot that already exists is never overwritten.
  • Insert: NO snapshot. A freshly created entity has no prior state by definition. Inside BuildRules, domain.Old(u) returns the typed zero value; defensive code with if old != nil guards Update-only rules.
  • List reads never snapshot. FindAll is the read-side path where no verb mutates, so it does not pay a per-row clone.

Manual handlers

A hand-written pipeline.Handler gets the same guarantee as an Auto one with no extra step, as long as it loads through the framework — persistence.LoadForWrite, the repository's FindByID / FindArchivedByID, or a custom repository finder built on read.AggregateLoader. All of them stamp the snapshot before the handler sees the entity. 

// Manual archive handler — nothing to remember: the load already snapshotted.
current, err := persistence.LoadForWrite[*Tenant](h.Repo, ctx, domain.NewID(cmd.PathID()))
if err != nil {
    return zero, err
}
if err := cmd.ApplyTo(ctx, current); err != nil { // mutates the live entity, NOT Old()
    return zero, err
}
archivable, err := domain.GetArchivable(current, h.Service, "GetArchivable")
// inside BuildRules: domain.Old(t).Status is the PERSISTED status

The one case that needs an explicit call is an entity hydrated some other way — a repository that does not use read.AggregateLoader, or an entity assembled in memory — that the handler intends to mutate before a Get*. Call domain.CaptureOld(e) immediately after hydration, before the first mutation. It is idempotent: a second call is a no-op, so the earliest snapshot always wins, and calling it late records the wrong state rather than erroring.

What the clone looks like

The clone is produced via a JSON round-trip (encoding/json) — only exported fields cross. Private BaseEntity/AggregateRoot state (notifCtx, events, signature) is intentionally NOT cloned, so the clone is a read-only “ghost”: calling mutator domain methods on it is a silent no-op because its notifCtx is nil. The aggregate path also copies the items map (aggregate value objects are value types, so the clone owns an independent view of the prior children) so Old() reflects the children as they were before mutation. The framework-owned domain.Managed carrier (the id + revision + managed timestamps a load surfaces on the root and every child) has unexported fields, so it does NOT cross the round-trip — the ghost carries the business fields of the prior state, not the framework's carrier. This is deliberate: Old() feeds BuildRules and the auditor, which speak business values, not the managed columns.

Because the round-trip rides encoding/json, the entity must not interfere with it: a persisted field tagged json:"-" would silently vanish from the ghost, and a custom json.Marshaler/json.Unmarshaler on the entity type would take the clone over. Both are boot panics at WithSchema — the old-clone safety boot check. Renaming tags (json:"name") are harmless (the round-trip is symmetric); entities simply should not carry wire tags at all — wire names live on the web-layer DTOs.

Audit event shape

The audit pipeline emits flat top-level fields — both as slog attrs on the echo line AND as top-level columns + JSONB payload on the audit_events row — with no nested envelope. The kind field discriminates the body block: snapshot (Insert / Delete), delta (Update / PartialUpdate), transition (Archive / Unarchive). Exactly one body block applies per event. 

{
  "msg": "audit",
  "threadId": "5f25…",
  "entityType": "User",
  "entityId": "abc-123",
  "verb": "update",
  "actionName": "GetUpdatable",
  "kind": "delta",
  "actor": "user-42",
  "actorIssuer": "https://idp.example",
  "actorClaims": { "tenant_id": "acme" },
  "dateTime": "2026-06-09T12:00:00Z",
  "changes": [
    { "field": "Email", "fieldLabelKey": "UserEmailField", "from": "a@x.com", "to": "b@x.com" }
  ],
  "children": {
    "Address": [
      { "id": "addr-1", "op": "updated",  "changes": [{ "field": "Label", "fieldLabelKey": "AddressLabelField", "from": "home", "to": "home renamed" }] },
      { "id": "addr-2", "op": "archived", "snapshot": { "Label": "work" } },
      { "id": "",       "op": "inserted", "snapshot": { "Label": "vacation" } }
    ]
  }
}

PUT and PATCH share verb: "update" — neither moves the row's archived state, so the lifecycle effect, and therefore the audit verb, is identical. The PUT vs PATCH distinction lives in actionName (GetUpdatable vs GetPartialUpdatable) — same way the domain unifies them via IfUpdate. Unchanged columns never appear in changes — no redundancy with the snapshot.

Aggregate children block

For aggregate roots (entities implementing AggregateRootProvider), the audit builder expands the event with a nested children map keyed by child typeName. Each entry carries {id, op, snapshot} or {id, op, changes} following the same kind discipline as the root event — enough to reconstruct a per-child timeline in ELK without parsing the outbox payload. Granularity stays B: one audit event per write, children nested inside, matching the “aggregate = event unit” semantic of the outbox.

Child op is lifecycle-grounded — every value echoes what the persister did to that row's existence and archived state. Same vocabulary as the root verb, no exceptions. See the Canonical write lifecycle section for the full effect ↔ op mapping; the table below summarizes the child cascade per root verb.

Custom infra escape hatch

Implementations that bypass both the framework's load path and its Get* path (raw SQL building an Updatable by hand — not exposed by the public API today, but conceptually) will not have Old() populated. On Update the audit builder's changes degrade to every column with from: null; on Delete it falls back to the live source's snapshot. Graceful degrade, not error.
