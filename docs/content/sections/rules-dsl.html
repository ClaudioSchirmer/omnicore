Rules DSL — IfXxx and actionName dispatch

Rules (domain/rules.go) exposes a mode-scoped DSL inside BuildRules: five IfXxx closures, each gating its body on the current EntityMode. The framework picks the mode; the caller picks the actionName (the last parameter on every Get* entry point — third for GetInsertable/GetArchivable/GetUnarchivable/GetDeletable, fourth for the closure-form GetUpdatable/GetPartialUpdatable). Auto handlers pass the canonical PascalCase string ("GetInsertable", etc.); manual handlers may pass any string. Service code branches by actionName inside the closure when a rule should fire only for a specific verb (typical use case: archive-only invariants under IfUpdate) or only for a specific endpoint flavor (e.g. "AdminCreate" vs canonical "GetInsertable").

r.IfInsert(func() { ... })
r.IfUpdate(func() { ... })          // fires for PUT, PATCH, Archive, Unarchive
r.IfDelete(func() { ... })
r.IfInsertOrUpdate(func() { ... })  // fires for Insert + every Update verb
r.IfDisplay(func() { ... })         // see "key facts" below — inert today

Key facts

  • Archive and Unarchive fire IfUpdate, not a dedicated IfArchive. Both run in ModeUpdate with a distinct actionName so the existing DSL covers state-transition verbs without growing the closure surface. Branch by actionName when archive-specific logic is needed (e.g. if actionName == "GetArchivable" { ... }).
  • The shared-base upsert fires IfInsert with actionName == "GetUpsertable" — there is no GetUpsertable function. The 7th Auto handler (SharedBaseInsertCommandHandler, the Party-Role upsert) still calls domain.GetInsertable in ModeInsert, but passes "GetUpsertable" instead of "GetInsertable" when the shared identity already existed (the warm path: load-first, apply on top, insert the role). So IfInsert sees one of two action names — "GetInsertable" for a cold first-time identity, "GetUpsertable" when an existing base is being re-used by a new role. Branch on it in BuildRules to relax or tighten rules for the upsert (e.g. tolerate a shared field already set by a sibling role): if actionName == "GetUpsertable" { ... }. The shared base's natural key is immutable (it derives the deterministic identity), so a rule that guards it should treat a change as an error.
  • actionName is case-sensitive. The Get* family emits PascalCase ("GetInsertable"); IsValid emits lowercase "isValid". Custom callers passing their own actionName (e.g. "AdminCreate" for stricter validation) must match the string exactly inside BuildRules.
  • AggregateValueObject.BuildRules receives the SAME actionName as the root. runAggregateValidations propagates the root's actionName verbatim when firing the AVO closures per child — so an AVO branching on actionName == "GetArchivable" matches the verb archiving the aggregate.
  • IfDisplay is inert in the canonical dispatch. ModeDisplay is the resting mode after framework initialization (the EntityMode zero value is ModeUnknown), but no framework path calls NewRules(ModeDisplay, ctx). The closure exists in the DSL for symmetry; using it today produces dead code unless an external caller wires its own dispatch.
func (u *User) BuildRules(actionName string, svc domain.Service, r *domain.Rules) {
    r.IfUpdate(func() {
        if actionName == "GetArchivable" {
            // archive-specific: e.g., "cannot archive primary account"
        }
    })
}
