Changelog

Notable changes to the framework, newest first — a consumer-facing digest of the public surface. The exhaustive, per-symbol list (Keep a Changelog format, SemVer) lives in CHANGELOG.md at the repository root. While in 0.x.y the public API may change between minor versions; breaking changes are called out under Changed. When you ship a feature, add a new release block at the top and bump the v… badge in index.html.

Unreleased—
  • Fixed — tabular export (CSV/XLSX) now respects the effective read projection, so ToCriteria is the single source of truth for which fields surface in every format. Before, a field a Query removed from ReadCriteria.Projection vanished from the JSON and from the CSV/XLSX values, but its column header survived — the export pruned its column plan by the wire ?fields alone, independent of ToCriteria. Now queries.Page carries a Projection (stamped by MongoViewReader.ReadPage), and the export narrows its plan via the new ExportPlan.PruneToProjection (the Go-path counterpart of Prune, honoring include / exclude / whole-doc modes) — so the header drops too. ?fields still drives the read projection and its validation. Build step toward field-level read Hide(). See Auto query handlers.
  • Changed — breaking: the Auto command/query mappers now raise notifications by return — every fallible boundary method returns error. ToEntity(ctx) → (T, error); FromEntity(ctx, t) → (TResult, error) on all six command verbs; ApplyTo(ctx, t) / ApplyPartiallyTo(ctx, t) → error; the query ToCriteria(ctx) → (ReadCriteria, error). domain.GetUpdatable / GetPartialUpdatable take apply func(T) error (propagated before validation). This lets the application (and infra) raise a notification from a mapper — e.g. an external-service failure inside ToEntity, or a field-access reject inside ToCriteria — through the idiomatic Go return path (errors.As at pipeline.Run), instead of being forced through the domain or a panic. The accumulate-then-gate facilitator stays domain-only, justified by the domain being the one sealed construction path (a ValidEntity cannot be hand-built). The Auto handlers propagate each mapper's error; pipeline.Run is unchanged. Every consumer mapper adds , error and a nil/propagated return. See Auto command handlers.
  • Changed — breaking: TableSchema.PK now takes only the column — PK("id") instead of PK("ID", "id"). The Go side of the primary key was never a free parameter: the domain.Entity/BaseEntity contract fixes identity to ID (an aggregate root carries it privately and exposes GetID/SetID; an AVO/child exposes the exported field ID), so only the physical column varies (id, person_pk, an upstream schema's own name). This aligns PK with the single-argument managed-column setters (CreatedAt / UpdatedAt / SoftDelete). Every call site drops the first argument. See TableSchema (PG + views).
v0.11.0June 19, 2026
  • Added — tabular export of a view query (CSV + XLSX, format-pluggable). fwweb.HandleQueryAsCSV[TReq, TQ] (and the generic HandleQueryExport) mount a route that streams the same view read as a paged GET — same Request DTO + query handler — as a flat file. Layout is hierarchical: root columns at column A, each embed one column deeper (infinite nesting). Headers come from each column's labelKey rendered in Accept-Language; ?fields= narrows columns (allowlist driven by the view schema); filters / ?search / ?sort / ?includeArchived behave like the JSON list; user pagination is ignored — the full filtered set is returned, capped at the resolved export ceiling. Format is a pluggable web/export.Encoder: export.CSV(export.WithDelimiter(r)) (separator chosen at mount) and export.XLSX(export.WithSheetName(s)) (Excel — bold headers, typed cells, built on excelize) both ship, via fwweb.HandleQueryAsCSV / HandleQueryAsXLSX; the neutral core (queries.ExportPlan + ViewDefinition.ExportPlan() + export.Generate) means a further format changes nothing else. See Auto query handlers.
  • Added — export wrappers take a web.ExportView interface (the *ViewDefinition satisfies it structurally, so web imports no infra) plus a web.ExportDeps{Translator, MaxExportRows} bundle pre-packaged on the new bootstrap.Deps.Export field. The wrapper resolves the plan, the row ceiling, and the download filename (view.Name()) internally, so an export route passes view, d.Export instead of view.ExportPlan() + d.Translator + view.ResolveMaxExportRows(d.Config.Query.MaxExportRows) + a filename by hand. Applies to all four wrappers (HandleQueryExport{,Spec}, HandleQueryAsCSV{,Spec}, HandleQueryAsXLSX{,Spec}). See Auto query handlers.
  • Added — openapi.RouteSpec.OmittedQueryParams []string: query parameter names dropped from the generated OpenAPI parameters even though RequestType declares them. The export *Spec wrappers reuse the JSON list's Request DTO but ignore pagination at runtime, so they list limit/after/before/onlyTotal here — Swagger stops advertising pagination knobs a CSV/XLSX export does not honor, while filters / ?fields / ?sort / ?search / ?includeArchived still render. Empty (no-op) for every other route. See OpenAPI / Swagger UI.
  • Added — ViewDefinition.MaxExportRows(n) + the query.maxExportRows yaml default — per-view / service-wide ceilings on export rows (cascade per-view > yaml > infra.DefaultMaxExportRows = 10000), resolved via ResolveMaxExportRows. Operational state — not in RebuildHash, mirroring MaxLimit.
  • Added — external-schema field labels: NewExternalSchema(table).Field(go, col, labelKey) declares a header catalog key inline on a type-less view source (an upstream collection with no Go struct to carry a labelKey:"…" tag). External-only — passing a label on a type-anchored NewTableSchema[T] is a boot panic (the struct tag stays the single source there). Field gains an optional trailing labelKey (backward compatible). Also domain.ToLowerCamel is now exported. See TableSchema (PG + views).
  • Added — TableSchema, the single mandatory explicit Go-field↔column map, supersedes the convention/inference model and the RepoConfig map. Built with NewTableSchema[T](table) (validates each field against T at construction — a typo is a boot panic) or NewExternalSchema(table) (type-less, for external FromSchema sources); chainable PK / FK / Field / SoftDelete / CreatedAt / UpdatedAt / Child. No name inference — every persisted field is declared; an undeclared exported field is runtime-only by construction. See TableSchema (PG + views).
  • Added — BaseAggregateRepository.WithSchema(*TableSchema) threads the one schema into the write binding and the read loader (write SQL + criteria + auto-scan); children come from the schema's Child(...) declarations.
  • Added — the same schema drives the Mongo read side: ViewDefinition.Schema(ts) (root) and fwinfra.FromSchema(ts) (embed). The composer writes physical columns; the reader translates each leaf back to its Go field name, so the typed Response speaks Go names with only json: tags.
  • Added — fwinfra.FromSchema(*TableSchema), the single embed source constructor: table/collection, store kind (type-anchored NewTableSchema[T] → local Postgres; type-less NewExternalSchema → external/Mongo), and the EmbedMany join FK are all derived from the schema. A local embed derives its Go segment from the schema's Go type (pluralized for EmbedMany); .As(...) is an optional override there and required on an external embed; .On(key) is one-to-one-Embed-only. Plus infra.ValidateViewSchemas (fatal boot enforcement that every view root + embed declares a schema, and every external embed declares .As) and the now-exported domain.PluralizeWord. See TableSchema (PG + views).
  • Removed — RepoConfig / SourceMap / ManagedColumn, WithChild / WithChildAutoScan / WithConfig, ViewOf[*T](), the view:"<docKey>" Response tag, the transient:"-" tag entirely (no longer read by any layer — a field is persisted iff declared in the TableSchema, and gets a label iff it carries a labelKey: tag), and the name-inference helpers (PluralizeSnake / PascalToSnake for persistence names). Manual scanners (WithRootScanner / WithChildScanner) remain.
  • Removed — the From(string) / FromMongo(string) string constructors and the Source.Schema(ts) method (replaced by FromSchema(ts)), plus the view.embed.schemaless boot advisory and its identity pass-through fallback (Source.SchemaDef() and the schema-less detection helper go with them). Schema is now mandatory on every view, not optional — there is no slog.Warn and no pass-through mode.
  • Changed — breaking: the field-label struct tag is now labelKey:"<catalogKey>" (was label:). The value has always been a catalog key the framework resolves to the rendered label (FieldLabelKey vs FieldLabel already name both ends); the tag now matches that vocabulary and no longer collides with domain fields named Label. The opt-out becomes labelKey:"-". Every consumer field declaring label:"…" must rename the tag; resolution is otherwise unchanged.
  • Changed — breaking: persistence names are no longer derived from Go identifiers; every Repository and view must declare a TableSchema and call WithSchema. Every view must declare a schema on the root AND on every embed; the embed's table, join FK, and store kind come from the schema (FromSchema); .On is now one-to-one-Embed-only and external embeds must declare .As. The read-side wire↔doc translation is a two-hop pivot — the web layer maps a wire path to the Go field path (via json: tags), and the reader translates the Go path → physical column (via the view's TableSchema). The aggregate-child notification segment is now camelCase (OrderLine → orderLines).
  • Changed — breaking: audit now speaks the faithful domain vocabulary — snapshot keys and changes[].field carry the raw Go field name (Email, ZipCode) instead of the snake_case column. Audit is map-blind, so a column rename never disturbs the timeline. Consumers keying audit on the old snake_case field names (e.g. ELK/BI pipelines) must update.
  • Added — the framework now actively stamps created_at = NOW() (and updated_at = NOW()) on write instead of relying on a DB DEFAULT it does not own; presence of CreatedAt(col) / UpdatedAt(col) on the schema enables each, omission disables it. The DEFAULT NOW() in the DDL becomes optional.
  • Added — a round of boot-time configuration guards that fail fast on misconfigurations the boot already has full knowledge of, instead of letting them surface as a runtime error or a silent no-op: auth.publicRoutes are validated against the registered route set (a typo / wrong method / trailing slash, or a path parameter / wildcard the exact-match middleware can never honor, aborts the boot); a declared integration.subscribes entry with no registered receiver aborts the boot (it would silently consume nothing); integration.subscribes…startFrom is enum-validated (earliest | latest); migration filenames without a parseable {version}_{name} prefix abort the boot (golang-migrate would silently skip them); the domain's AggregateChildren() and the schema's .Child(...) must name the same set; httpClient.authProviders…tokenEndpoint must be an absolute URL; and signing signedHeaders may not name the policy's own signatureHeader / keyIdHeader.
  • Added — BaseRepository.WithSchema(*TableSchema), the validated canonical way to bind a schema on a flat (non-aggregate) repository — runs the PK-declared, aggregate-depth, and Modes() ⟺ SoftDelete checks at construction (the same the aggregate path runs) rather than on the first write. Assigning r.Schema directly stays supported as the unchecked escape hatch.
  • Added — two more Mongo boot validations in ValidateMongoSpec: every view index key must name a column the composer emits (a typo or a Go field name instead of the physical column would be a dead index), and every top-level $jsonSchema.required entry must too (otherwise, under the default validationAction: error, Mongo rejects every SyncEngine upsert and silently freezes the projection). Both abort the boot naming the offending field.
  • Fixed — integration consumer topology: a source declaring two or more events (From(s).On(A).On(B)) no longer drops roughly half of every event type. The Kafka consumer is now one reader per (topic, consumerGroup) that demultiplexes by event_type to the matching receiver, instead of one reader per receiver (two readers shared the coordinate, Kafka split the partitions, and each silently auto-committed the events meant for the other). Two receivers resolving to the same (topic, consumerGroup, event_type) now abort the boot.
