v0.32.1July 15, 2026
  • Fixed — docs-only: the "Domain Service via Auto handler" example dereferenced *u.GetID() inside IfInsertOrUpdate. On Insert the id is minted after validation, so GetID() is nil inside BuildRules and the example, copied verbatim, panics with a nil-pointer dereference on the first insert. The example now nil-guards and passes a zero excludeID — which excludes nothing, exactly right for a brand-new entity. No Go code changed. See Auto command handlers → Domain Service via Auto handler.
v0.32.0July 14, 2026
  • Changed — breaking: old-clone safety is now a boot check — a persisted field tagged json:"-", or a custom json.Marshaler/json.Unmarshaler on the entity type, panics at WithSchema. The framework builds the domain.Old() pre-write snapshot (consumed by BuildRules transition checks and the transition auditor) by cloning the root entity through an encoding/json round-trip, so a json:"-" persisted field silently vanished from the ghost — the prior state read back as the zero value — and a custom (un)marshaler took the round-trip over entirely; both corrupted rules/audit with no visible failure. The check covers every field persisted through the root struct (the root's declared fields, sibling partitions, and shared-base fields resolved on the role's type); aggregate children are exempt (the clone copies them by value, never through JSON), and renaming tags (json:"name") remain allowed — the round-trip marshals and unmarshals the same type, so renames are symmetric. Migration: drop the json:"-" tag (wire names belong on the web-layer DTOs) or move the custom JSON codec off the entity type. See Table schema → Boot checks and Old-state snapshot.
v0.31.0July 14, 2026
  • Changed — breaking: every framework control-plane table now follows the framework's own id standard — a UUID v7 minted in Go as the PRIMARY KEY, stored in the dialect's native id form (UUID on Postgres, BINARY(16) on MySQL/SQL Server), no AUTO_INCREMENT/BIGSERIAL/IDENTITY/DB default anywhere. omnicore_mongo_views and omnicore_integration_processed gain the same surrogate PK with their former natural keys preserved as UNIQUE constraints (lookups still key on the natural columns). Wire-crossing id references (outbox.aggregate_id, the integration_events uuid columns, audit references) are canonical uuid TEXT (CHAR(36)) on EVERY dialect — Postgres included — because they cross the Debezium/Kafka boundary as strings. UpstreamFailureRecord.ID/IntegrationFailureRecord.ID are now uuid strings (were int64); the admin replay pages by keyset over the PK. Performance notes in the same rewrite: uuid-text reference columns carry binary/ASCII collations (memcmp comparisons; values are always the lowercase canonical form), the dedup pre-check is an index-only probe on the natural-key UNIQUE, and the outbox drops its (aggregate_type, aggregate_id) index — no framework code SELECTs the outbox by aggregate (Debezium reads the log/CDC, not the table); created_at stays for pruning. Migration: the 0001_framework files were rewritten in place (pre-1.0) — recreate the framework control plane (bench: docker compose down -v). See Migrations.
  • Added — SQL Server joins PostgreSQL and MySQL as a first-class relational engine. A complete engine ships behind the sqlserver build tag (infra/db/engine/sqlserver, driver microsoft/go-mssqldb): selecting relational.dialect: sqlserver + go build -tags 'sqlserver <transport>' runs a service on SQL Server through the same engine seam as the other backends — same write path (one TX for data + outbox + audit), criteria reads, composer projection, rebuild lock, migration runner, admin tooling. Dialect specifics: @pN placeholders, bracket-quoted identifiers, a single-statement MERGE … WITH (HOLDLOCK) upsert, CURRENT_TIMESTAMP as the now expression, a SELECT-head TOP n row cap, unique/FK classification from errors 2627/2601/547, and a session-owned sp_getapplock rebuild lock. Identity is stored BINARY(16), never UNIQUEIDENTIFIER — SQL Server orders GUIDs last-byte-group-first, which would destroy the UUIDv7 time order and fragment the clustered PK; BINARY(16) compares bytewise, so the Go-minted v7 ids keep the clustered index append-friendly. JSON rides as NVARCHAR(MAX) text. The control plane ships as embedded/sqlserver/0001_framework.{up,down}.sql (filtered indexes where PG uses partial ones; constraint names identical across dialects so a ConstraintBinding maps the same violation on every backend) with its own runner (migration.NewSQLServer). Internal enablers, no consumer surface: the bootstrap engine twins collapsed into a per-dialect boot registry (any engine-tag combination now links into one binary), and the control-plane JSON payloads bind as text (byte-identical on PG/MySQL). See TableSchema → Supported column shapes — Go ↔ SQL Server, Architecture, Migrations and Bootstrap.
  • Changed — core.Dialect gains the savepoint trio — Savepoint/RollbackToSavepoint/ReleaseSavepoint. The shared-base orphan purge used to emit the standard savepoint literals; T-SQL spells them SAVE TRANSACTION/ROLLBACK TRANSACTION and has no release statement (ReleaseSavepoint returns "" on SQL Server; the caller skips it). Each engine's Dialect now lives in its own dialect.go.
  • Changed — the last dialect-specific SQL literals left shared code: core.Dialect gains NowExpr() and ApplyLimit(sql, n). Shared statement builders used to bake in NOW() (managed created_at/updated_at stamps, the soft-delete archive stamp, the outbox created_at, the failure registries' timestamps) and a tail LIMIT n (existence probes, FindOne's bounded load, the composer's row fetches) — both parse on Postgres AND MySQL, so the coupling was invisible, but neither would survive a third engine. Every generated statement now obtains its current-timestamp expression from Dialect.NowExpr() and its row cap from Dialect.ApplyLimit(sql, n), which receives the COMPLETE SELECT so an engine whose cap is not a tail clause (e.g. a SELECT-head TOP n) can rewrite the statement. Both engines render exactly the SQL they rendered before (NOW() / trailing LIMIT n), so no emitted statement changes and no consumer action is needed; the operator-facing drift-reconcile scripts, which have no dialect at hand, switch from NOW() to the ANSI CURRENT_TIMESTAMP. Groundwork for a future SQL Server engine — see Architecture → The relational-engine seam.
v0.30.0July 13, 2026
  • Changed — breaking: identity is a TYPE — domain.ID becomes the persistable identity field type, and the MySQL value-shape codec heuristic is removed. A field holding an id (a cross-aggregate reference like a BuyerID/TenantID) is declared domain.ID — nullable ⇒ *domain.ID — and the field's Go type alone drives every leg on every supported engine: the write bind and the criteria probe lift render the dialect's native id form (UUID on Postgres, BINARY(16) on MySQL) and the new id scan proxies restore it on read, with nil ⇄ SQL NULL on the pointer (a nullable BINARY(16) reference was previously impossible). A plain string field is text, ALWAYS — the old MySQL heuristic that bound any canonical-shaped uuid string as 16 raw bytes is gone, so CHAR(36)/VARCHAR(36) uuid-valued text columns are first-class; nothing is guessed from a value's shape. Managed PK/FK slots are unaffected (bare-string ID probes like the exclude-self Ne("ID", id) are lifted by construction). Migration (MySQL consumers only): retype every uuid reference field stored as BINARY(16) from string to domain.ID (*string → *domain.ID) — DDL and data stay exactly as they are; text-stored fields keep string. Postgres consumers break nothing unretyped (text binds serve UUID columns either way). See Table schema → Supported column shapes.
  • Changed — breaking: the identity contracts speak domain.ID end to end. Every contract that carried a bare id string is retyped: Updatable/Archivable/Deletable/Unarchivable.ID() return domain.ID (the redundant IDValue() twin is absorbed — one method, one type; Insertable.ID() already returned *domain.ID), AggregateValueObject.GetID() returns domain.ID and the documented AVO shape carries an exported ID domain.ID field (the persister's minted-id write-back sets it via reflection and rejects any other type), domain.WriteResult.ID is domain.ID (its JSON shape is unchanged — the ID marshals to the canonical string), and criteria.ByID takes domain.ID. Migration: mechanical — AVO structs retype ID string → ID domain.ID (GetID returns it directly); call sites needing text call .Value(); IDValue() becomes ID(); bare-string ByID(s) becomes ByID(domain.NewID(s)). See Aggregate persistence.
  • Changed — breaking: the persistable field-type set is CLOSED — an unknown Go type is a boot fail at the Field(...) declaration. The type-driven contract makes the field's type its storage declaration, so the set of declarable types is now validated at construction against exactly what the framework composes on every supported relational engine (the "Supported column shapes" tables): string/bool/int·16/32/64/float32/64/time.Time — each plus its pointer form — domain.ID/*domain.ID, []byte, json.RawMessage. A google/uuid.UUID field panics with the dedicated hint (declare domain.ID); every other unknown type — named enums, structs/maps, Go slices (the former PG-only array mapping) — panics pointing at Table schema, the canonical home of the supported set, with the mapping fix (enum → its underlying string/int, JSON payload → []byte/json.RawMessage, collection → JSON column or an aggregate Child(...)). Matching is by identical type, never by kind. Migration: a schema declaring one of the removed exotic mappings fails loudly at first boot with the message above — remap the field.

v0.28.0July 12, 2026
  • Changed — breaking: sibling schemas reject every identity/lifecycle declaration at the declaration call — including the previously half-honored managed timestamps. A sibling is a 1:1 slice of the OWNER's row: it borrows the owner's PK — the sibling table's physical PK column must carry the SAME NAME as the owner's PK column (an FK-style <owner>_id column used to surface only as an Unknown column 500 at the first write) — the shared PK is the link (no FK), and the owner controls lifecycle and dating. PK/FK/SoftDelete already panicked at Sibling(...) attach; they now fail earlier, at the call itself, with messages that teach the DDL contract. CreatedAt/UpdatedAt on a sibling — previously accepted and stamped on INSERT but never re-stamped on UPDATE (a silently stale timestamp) — are now rejected the same way: declare them on the owner. See Table schema → Sibling tables.
  • Added — AggregateBy + read.By: the grouped half of the aggregate DSL — the same typed scalar facts, computed per GROUP BY group in ONE SELECT. The v0.27.0 DSL answers "how many / how much over THIS criteria"; a rule over per-group facts (per-category caps, distinct-key cardinality, balance checks) still had to fetch rows and bucket them in Go. AggregateBy(ctx, q, read.By("Category"), specs…) compiles SELECT <keys>, <specs> … GROUP BY <keys> ORDER BY <keys> under the same criteria, field resolution (sibling/shared-base fields pull their LEFT JOINs) and active-by-default scope gate as Aggregate. The passed specs act as templates (they carry no result); each returned read.Group holds its own copy of every fact, read back type-safely via read.GroupResult(group, template) — the template's concrete type, no assertion — plus Key/KeyString access to the group key(s) by Go field name (driver-neutral: MySQL's []byte text keys land as string). An empty set yields zero groups; len(groups) is the distinct-key cardinality; a group's spec reports Found=false only when every matched row holds NULL in that column; groups come back ordered by key ascending. Order/limit on the Query are ignored, exactly like Aggregate. Both drivers proven by integration tests. See Custom command handler → Grouped aggregates.
v0.27.0July 12, 2026
  • Added — Exists and the aggregate DSL (Aggregate + typed specs) on the aggregate loader: hydration-free scalar facts for write-path business rules. FindAll was the only criteria read, so a uniqueness pre-check inside a domain.Service paid a full aggregate load to answer a yes/no question. Exists compiles to a bare SELECT 1 … LIMIT 1; Aggregate(ctx, q, specs…) computes any combination of scalar facts over the same criteria in ONE SELECT — each fact is a typed spec carrying its own result: read.Count() (int64), the exact-integer trio read.SumInt/read.MinInt/read.MaxInt (the money shape, int64 minor units; a fractional scalar errors loudly) and the float64 quartet read.Sum/read.Avg/read.Min/read.Max. Field specs carry a Found flag distinguishing "the value is 0" from "no row matched". Same field resolution as FindOne/FindAll (sibling/shared-base fields pull the same LEFT JOINs), same active-by-default scope gate, nothing hydrated. The PK is addressable in criteria as the fixed Go field "ID", so the exclude-self uniqueness shape is one expression: Where(And(Eq("Email", v), Ne("ID", excludeID))). Both drivers proven by integration tests (Postgres NUMERIC via pgtype.Numeric, MySQL DECIMAL as text — normalized exactly). See Custom command handler → Loading by criteria.

v0.24.0July 12, 2026
  • Fixed — docs: the CDC relay must pass the outbox payload through as opaque text — JSON expansion off. The transport section now states the relay config contract explicitly: table.expand.json.payload=false + the pass-through value format (Debezium Server simplestring / Kafka Connect StringConverter). With expansion on, Debezium infers a typed schema from each event's JSON text, and JSON number shapes are not stable types (Go marshals the float 3.0 as 3) — a numeric array like [3.7, 3] fails the expansion and crashes the relay, halting all read-model refresh on a poison message. No OmniCore consumer reads the typed structure (the payload is a routing hint; the composer re-reads the database). An item without a settable string ID field is skipped silently. No change to the write path's API. See Aggregate persistence.
v0.23.0July 11, 2026
  • Fixed — a SharedBase base with a second unique column no longer 500s on MySQL. The shared-identity write was a DB-native upsert; Postgres' ON CONFLICT (pk) is scoped to the primary key, but MySQL's ON DUPLICATE KEY UPDATE fires on any unique key — so a base with a second unique column (e.g. a unique email beside the natural-key PK) let a new-identity write whose email already existed hijack the upsert onto the wrong persons row (new base never inserted → role FK fails → 500 instead of a clean 409). The shared-base write is now an explicit INSERT (new identity) / UPDATE by PK (existing identity) branch — identical on both dialects — so a second unique column raises a normal unique violation the repository's ConstraintBinding maps to 409, restoring backend parity. Two concurrent COLD inserts of the same brand-new identity now yield one PK-conflict 409 instead of a silent last-write-wins merge. No API change. See TableSchema → Shared base.
v0.22.0July 11, 2026
  • Changed — breaking: the liveness probe moved from GET /health to GET /livez. Renamed to the Kubernetes-idiomatic -z family — the pair /livez + /readyz (k8s core itself retired the single /healthz). Behaviour is otherwise identical: static {"status":"ok"}, no dependency checks (a liveness probe must fail only when a restart is the cure, never on a store blip). /health is no longer a reserved route; /livez and /readyz are (the openapi.uiPath / graphql.path collision set). Migration: update every auth.publicRoutes entry (GET /health → GET /livez, add GET /readyz), any k8s/Docker probe path, and any hard-coded /health caller. See Bootstrap.
  • Added — HTTP server hardening knobs. Three optional http: fields, each left at Fiber's default when unset: bodyLimitBytes caps the request body (a larger body → 413, rendered by the existing envelope; unset → Fiber's 4 MiB default), while readTimeoutSeconds and idleTimeoutSeconds are transport-level (fasthttp) slowloris/keep-alive defenses. A read timeout surfaces as 408 Request Timeout (the new ReadTimeoutNotification — the client was too slow, a 408, not a misleading 500), written best-effort before the connection closes; an idle timeout silently closes the keep-alive with no response. Both are distinct from requestTimeoutSeconds, which bounds handler processing and maps to 504. Negative values are rejected at boot. See YAML reference and Status mapping.
  • Changed — graceful shutdown is now bounded no matter what. A context is cooperative — it cannot interrupt a stage that ignores it — so the drain budget alone never guaranteed the process would actually exit. Three defences close the gap: the final tracing flush runs on its OWN short budget (shutdown.tracingDrainSeconds, default 5s) so a dead/slow OTLP collector can't consume the whole window; the onShutdown hook is raced against the drain deadline instead of awaited inline, so a hook that blocks ignoring its context can no longer stall the process; and a watchdog force-exits at drainTimeoutSeconds + shutdown.hardGraceSeconds (grace default 5s) while a second SIGINT/SIGTERM exits immediately. The gRPC listener is also force-closed when its graceful Shutdown overruns, and the final Mongo disconnect is bounded by a 5s timeout. Fixes a real hazard — a dead OTLP collector during a rolling deploy could otherwise burn the full window and get SIGKILLed mid-flush. Not breaking: defaults preserve behaviour; only a shutdown already overrunning is now cut short. See Bootstrap → Graceful shutdown.
  • Added — graceful-shutdown drain knobs — shutdown.tracingDrainSeconds, shutdown.hardGraceSeconds. Two optional shutdown: fields beside drainTimeoutSeconds. tracingDrainSeconds (default 5) is the telemetry-flush sub-budget; hardGraceSeconds (default 5) is the watchdog margin over the drain budget, and a negative value disables the watchdog (an embedder owning the process lifecycle). Both default when 0/absent — an upgrade with no yaml change gains the bounded behaviour. See YAML reference and Bootstrap.
  • Added — readiness probe — GET /readyz. A Kubernetes readiness probe alongside liveness: 200 when the request-path stores respond and the process is not draining, 503 otherwise (k8s removes the pod from the load balancer, not restart it). On SIGTERM it flips to 503 immediately — the missing half of the coordinated drain, so the balancer stops routing new traffic while in-flight requests finish (derived from the same signal.NotifyContext that governs the drain). It pings the relational backend (dialect-neutral SELECT 1) and Mongo under a short deadline; the message transport is deliberately excluded — the outbox decouples writes from the broker, so a broker outage still lets the pod commit writes and serve reads, and async-consumer health is an alerting concern, not readiness. Framework-owned but not auto-public — list it in auth.publicRoutes so a tokenless kubelet can reach it. See Bootstrap.
  • Fixed — docs: a service's own migrations start at 0001, not 0002. The numbering guidance said services begin at 0002+, which was wrong: the framework's 0001_framework is tracked in a separate table (omnicore_framework_migrations) from the service's own (omnicore_migrations), so the two sequences never collide and a service numbers its files independently from 0001. No behaviour change — the runner always supported this. See Migrations.

v0.5.0June 15, 2026
  • Changed — breaking: upgraded Fiber v2 → v3. Breaking across the HTTP layer: handlers take fiber.Ctx (interface, no pointer), body/query binding moves to the unified c.Bind() API, and several config shapes change. Consumer services upgrade in lock-step after the framework tag is cut.
  • Changed — bumped pgx to v5.10.0 (security hardening, no breaking changes).
  • Removed — thin wrappers web.CORS, web.Logger, web.RateLimit (call the Fiber v3 middleware directly). web.Recover() is kept for its slog-integrated stack handler.
v0.4.0June 14, 2026
  • Added — parameterized notifications: tvar:"<name>" struct tags substitute runtime values into translated messages, with per-emit Vars overrides and the new Translator.Render / Interpolate surface.
  • Changed — persistence.TxHandle is now a sealed marker with no public methods; infra.UnwrapPgxTx is the single authorized bridge to the underlying pgx.Tx, making "application is SQL-free" a type-system guarantee.
