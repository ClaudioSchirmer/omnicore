Domain events — a fact the entity itself announces

A domain event is a fact an entity records about itself during a write: "this user's password was reset", "this contract was renewed under the grandfathered rate". The entity registers it while the business rules run; the framework publishes it after the transaction commits, through a port the service can replace.

Three neighbouring things, three different jobs. Audit is forensics the framework writes for you — one event per write, derived from the entity, never authored by hand. A domain event is the entity's own sentence, authored in domain code, about something audit's snapshot/delta vocabulary cannot say. Integration events are the cross-service channel — written in-TX to integration_events, relayed to a broker, consumed by another service. A domain event never leaves the process on its own: its default transport is this service's own log stream.

Registering one

RegisterEvent is promoted onto every entity from domain.BaseEntity. Call it from domain code — a root method, a rule closure — while the write is still being assembled: 

func (u *User) ResetPassword(hash string, byAdmin bool) {
    u.PasswordHash = hash
    u.RegisterEvent(domain.DomainEvent{
        Type:  domain.EventWarning,
        Class: "User",
        Msg:   "password reset",
        Vals:  map[string]any{"byAdmin": byAdmin},
    })
}
FieldTypeCarries
Typedomain.EventTypethe severity — see the table below. The zero value is EventUnknown
Classstringthe entity type the fact is about; surfaces as entityType, omitted when empty
Msgstringthe sentence; surfaces as message, omitted when empty
Valsanyfree-form structured payload; surfaces as values, omitted when nil
Reasonerroran error the fact is about; surfaces as exception (its Error() string), omitted when nil

DomainEvent satisfies the domain.Event interface (EventType/ClassName/Message/Values/Err), which is what the publisher consumes — a service with a richer event type of its own can implement that interface instead of using the struct.

The four severities

domain.EventType is a closed set with explicit numeric values (reordering the block must never change a persisted number). The severity is the only thing the framework reads from an event: the default publisher maps it to the slog level.

ConstantValueString()slog level
domain.EventLog1"log"Info
domain.EventDebug2"debug"Debug
domain.EventError3"error"Error
domain.EventWarning4"warning"Warn
domain.EventUnknown0"unknown"Info (the fallback)

EventUnknown is the zero value, so an event constructed without a Type still publishes — at Info, spelled "unknown". Set the severity deliberately.

When it is published — and what that costs

Every write verb hands the entity's accumulated Events() to the write engine alongside the audit event. They are published from the single post-commit position, the same one that emits the audit slog echo — so a domain event is only ever announced about a write that actually landed.

  • Independent of audit. The events ride along whether or not any audit.destinations is active — turning audit off does not turn domain events off.
  • Best-effort, never load-bearing. A publisher error is logged as slog.Warn "event.publish.error" and swallowed. The write is already committed; a failing transport must not turn a successful write into a failure. Do not put anything you cannot afford to lose behind this port — that is what integration events (in-TX, at-least-once) are for.
  • Outside the transaction. A publisher runs after COMMIT and gets no TxHandle. For an in-TX side effect, use a lifecycle hook.
  • Per write, then cleared. The accumulated events are part of the entity's per-operation state and are reset along with it, so a re-validated entity does not re-announce what it already announced.

The default transport — SlogPublisher

bootstrap.Run wires events.NewSlogPublisher(logger) onto the relational engine automatically, so domain events work with no configuration. Each event becomes one record on the always-on JSON stdout channel under the message "event", with a vocabulary deliberately aligned with the audit echo so log queries match across both: 

{"level":"WARN","msg":"event","threadId":"3f2a…","eventType":"warning",
 "actor":"auth0|42","dateTime":"2026-08-22T18:04:11Z","entityType":"User",
 "message":"password reset","values":{"byAdmin":true}}

threadId, eventType, actor and dateTime are always present — the first three read off the AppContext, the timestamp stamped in UTC at publish time. entityType, actorIssuer, message, values and exception appear only when the event carries them.

No actorClaims, by design. The JWT claim allowlist (auth.auditClaims) broadens what audit may log and nothing else; a domain event carries the actor and its issuer, never the claim set.

Replacing the transport

events.Publisher is a port: implement it to send domain events somewhere other than the log stream — a metrics counter, an in-process bus, a dedicated sink — and install it on the engine at the composition root. A nil publisher disables the feature. 

type Publisher interface {
    Publish(ctx persistence.RequestContext, event domain.Event) error
    PublishAll(ctx persistence.RequestContext, events []domain.DomainEvent) error
}

// composition root — chainable, same seat bootstrap uses for the default
engine.WithEventPublisher(myPublisher)

PublishAll is what the write path calls; SlogPublisher implements it as a loop over Publish that stops at the first error, so a custom implementation that wants every event delivered regardless should not propagate one event's failure. Remember the caller swallows whatever comes back: the return value only decides whether the framework logs its warning.
