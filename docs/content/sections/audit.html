Audit

Every successful write emits exactly one AuditEvent — the forensic record of what changed, who changed it, and when. Audit travels with the persister: each write through the relational engine (Insert / Update / Archive / Unarchive / Delete) builds the event and routes it according to the boot-time audit.destinations configuration. There is no Auditor singleton to thread through handlers — it is configured once at boot (WithAudit(...) on the relational engine) and every write, Auto or manual, is covered without a line of handler code.

The event is the byproduct of the write path documented in the Write lifecycle map (whose last column is the audit verb). This page details the event itself: its JSON shape, the snapshot/delta/transition body discriminator, the children cascade, the actor stamping, the translated field labels, and the two destinations — slog (observability echo, ELK/Loki/Datadog) and database (an atomic, in-transaction row in audit_events for compliance) — plus the pre-built backend-neutral read helpers (read.NewAuditReader, which works on Postgres or MySQL).

How it works — granularity B, atomic with the write

The audit unit is the aggregate operation (granularity B), mirroring the single outbox row the same write produces. One repo.Method() call → one AuditEvent, regardless of how many child rows the aggregate touched; children contribute to the event's children block, not to separate events. The dateTime is captured at ValidEntity construction, so it reflects the moment the domain accepted the operation, not when the row was flushed.

engine.Insert/Update/Archive/Unarchive/Delete │ ▼ BEGIN TX │ data write (root + children when aggregate) │ INSERT outbox ← one row, granularity B │ IF destinations ∋ database: │ audit.InsertAuditEvent(ctx, tx, ev) ← row in audit_events, SAME TX ▼ COMMIT │ ▼ (POST-COMMIT, best-effort echo) IF destinations ∋ slog: audit.EchoSlog(ctx, logger, ev) ← flat slog line for shippers

The database row is written inside the same transaction as the data row and the outbox row — so a crash between writes can never leave an audit gap. If COMMIT succeeded, the audit row exists. The slog echo fires after COMMIT and is best-effort: lossy if the log shipper drops the line, but the PG row stays authoritative. The model + read port + label renderer live in application/audit (event.go the event, reader.go the Reader port, render.go the label renderer), so an application/web consumer reading the timeline depends on the abstraction, not on infra. The implementation lives in infra/audit/persister.go (the in-TX writer), infra/audit/reader.go (the concrete reader), infra/audit/echo.go (the slog echo), and infra/db/command/write/audit_builder.go (the per-verb builders).

Two destinations — slog and database

DestinationMechanismWhenGuaranteeUse for
database audit.InsertAuditEvent → row in audit_events inside the write's transaction atomic — the row IS the audit; if the write committed, the audit exists compliance, forensics, source-of-truth timelines joinable to other PG state
slog audit.EchoSlog → flat top-level slog line after COMMIT best-effort echo — lossy if the shipper drops it observability pipelines (ELK / Loki / Datadog / stdout collector)

Routing is declared in microservice.<profile>.yaml. The block is optional; an absent block (or absent destinations: key) defaults to both destinations active — the recommended posture (PG row guarantees compliance; the slog echo feeds whatever observability stack the operator already runs). 

# Default posture (both) when the block is omitted entirely.
audit:
  destinations:
    - slog        # post-commit echo for ELK / Loki / stdout collectors
    - database    # in-TX row in audit_events (atomic with the write — source of truth)
  # destinations: [database]   # only the PG row — highest signal/noise, lowest log volume
  # destinations: [slog]       # only the slog line — observability-only posture
  # destinations: []           # explicitly disables audit (no row, no slog line)
ValueEffect
block absent / destinations: absentboth slog + database active
[database]only the PG row
[slog]only the slog line (pre-redesign observability-only posture)

[kafka] (unknown) / [slog, slog] (duplicate)boot aborts with a diagnostic naming the offender

The audit_events table is provisioned unconditionally by the framework's embedded migration 0001 — even with destinations: [] the table exists; it just never receives a row. The companion knob auth.auditClaims (a JWT-claim allowlist) lives under auth: because it is a security concern — it whitelists which claims leave the JWT envelope into actorClaims; it is not a routing knob.

Body block — snapshot / delta / transition

Exactly one body regime applies per event, selected by kind:

kindVerbsCarriesWhat's in the block
snapshot insert, delete snapshot: map[goFieldName]value full state — post-insert for Insert; pre-delete (via Old()) for Delete
delta update changes: [{field, fieldLabelKey, from, to}] sorted by field only mutated fields; unchanged ones absent. field is the faithful domain name (the raw Go field name, e.g. Email) — audit is map-blind, never the physical column. fieldLabelKey (omitempty) carries the catalog key from the field's labelKey:"…" tag
transition archive, unarchive (neither block) the verb itself is the recovery hint — a symmetric inverse

PartialUpdate (PATCH) shares verb: "update" with PUT because the SQL is identical (UPDATE … SET col=val, updated_at=NOW()); the PUT-vs-PATCH distinction lives in actionName (GetUpdatable vs GetPartialUpdatable) — the same unification the domain applies, where IfUpdate fires for both. See the Write lifecycle map for the full verb → SQL → audit table.

Children cascade

The children map appears when the source implements AggregateRootProvider and at least one child is observable for the verb. Keyed by Go type name (Address, OrderLine); each entry carries {id, op, snapshot} or {id, op, changes} following the same kind discipline. Child ops are SQL-grounded — every op echoes the SQL fingerprint of the row-level change. For an update root, the op is decided by domain.OperationOf(OriginalStatus, CurrentStatus) (where the child started vs where it is now), not by its current status alone — so a DB-loaded child re-added is updated (not inserted), and a brand-new child added then removed before commit produces no entry (OpNoop):

Root verbChildren includedPer-child opSQL on the child row
insertall currentinsertedINSERT INTO addresses (...)
update — OpInsertbrand-new child kept (added, never DB-loaded)insertedINSERT INTO addresses (...)
update — OpUpdateDB-loaded child changed OR re-added (Constructor→Changed/Added)updatedUPDATE addresses SET col=val, updated_at=NOW()
update — OpDeleteDB-loaded child removed (Constructor→Removed)archivedUPDATE addresses SET deleted_at=NOW() (row stays, recoverable)
update — OpNoopuntouched DB child (Constructor→Constructor) OR new-then-removed (Added→Removed) — both skipped—(no SQL, no entry)
archiveevery loaded active child (cascade)archivedUPDATE addresses SET deleted_at=NOW() WHERE user_id=$1 AND deleted_at IS NULL
unarchiveevery loaded archived child (cascade)unarchivedUPDATE addresses SET deleted_at=NULL WHERE user_id=$1 AND deleted_at IS NOT NULL
deleteevery loaded childdeletedexplicit DELETE FROM addresses WHERE user_id=$1 per child table (same TX, before the root DELETE)

For flat entities (no AggregateRootProvider) the children block is absent. UPDATED children pair pre/post by GetID() against the deep-copied prior root's aggregates map (see Old-state snapshot).

SharedBase roles — whole-object composition

When the audited entity is a SharedBase role, its fields are partitioned by infra across the shared-base table (identity, shared by every role), the role's own table, and any siblings — yet the audit timeline speaks the whole domain object, not one table. The snapshot (insert/delete) and the changes delta (update) compose over the role's own fields ∪ its shared base's fields ∪ its siblings' fields, so a mutation of a shared base field (e.g. the natural key or a shared attribute) appears in the delta exactly like a role-own field. Base fields are read by Go field name off the flat role entity — the same access the base UPSERT uses — because the base schema is type-less. fieldLabelKey resolves across all three schemas.

Base-children (1:N collections owned by the shared base, shared by every role) appear in the children block under their Go type name with a populated per-op snapshot/changes, identical in shape to a role-own child — the child walk resolves both role-own and base-owned collections. A flat, non-SharedBase entity is unaffected: the composition degenerates to the root's own fields.

Actor & claims

The persister reads the authenticated principal straight from the request scope (persistence.RequestContext, satisfied by *AppContext) — so the actor is stamped for both Auto and manual handlers without any handler-side code, because every write goes through repo.Scope(ctx, …) and ctx IS the *AppContext the auth middleware populated.

  • actor — JWT sub, or "anonymous" when no Identity is attached (auth disabled, public route, background job).
  • actorIssuer — JWT iss; omitted when empty.
  • actorClaims — the subset declared by auth.auditClaims. Empty / absent allowlist → the block is omitted entirely; the signing-secret-style claims you never declared do not leak.

Field labels — translated identifier on the audit row

The audit field (the raw Go field name, e.g. Name, ZipCode) is a technical identifier — stable but not human-readable. For compliance / ouvidoria / BI readers a labelKey:"<catalogKey>" struct tag on the domain field declares a catalog key the audit pipeline writes onto FieldChange.FieldLabelKey in every delta change (top-level and child). The full declaration mechanism — shared with the notification wire — lives under HTTP status mapping → Field labels; here is the audit-side behavior.

Audit stores the key, not the rendered string. The row is an immutable artifact; the catalog evolves and a compliance team may read in any locale, so the key persists and the label is rendered at read time. 

{
  "verb":   "update",
  "kind":   "delta",
  "changes": [{
    "field":          "Name",
    "fieldLabelKey":  "UserNameField",
    "from":           "Jane Doe",
    "to":             "Jane Smith"
  }]
}

snapshot blocks (Insert / Delete) carry map[goFieldName]value with no schema for labels and are intentionally not labeled. Fields without a labelKey tag emit no fieldLabelKey (omitempty elides it).

Reading audit rows — backend-neutral reader

When destinations includes database, the framework ships a generic audit.Reader port with two canonical lookups. Build it once over the booted engine with read.NewAuditReader(deps.DB): it runs through the engine's neutral read seam (Querier + Dialect), so the same code reads audit_events on Postgres or MySQL — the audit trail stores ids as UUID text (Postgres UUID / MySQL CHAR(36)), so the reader binds them verbatim with no per-dialect value codec. 

// Build the reader once over whichever relational engine booted (Postgres or MySQL).
reader := read.NewAuditReader(deps.DB)

// Forensic single-row lookup — you saw an id in the slog echo and want the full row.
ev, err := reader.FindByID(ctx, eventID)
if errors.Is(err, audit.ErrAuditNotFound) {
    // no row with that id — partition pruned? archived?
}

// Timeline by aggregate — index-served by audit_events_entity_timeline_idx
// (entity_type, aggregate_id, occurred_at DESC). Newest first.
events, err := reader.FindByAggregate(ctx, "User", userID.String())
for _, ev := range events {
    // walk the row's lifetime
}

The returned *AuditEvent mirrors what the persister wrote: top-level columns map directly; the payload jsonb blob unmarshals back into Snapshot / Changes / Children. Render the catalog labels in any locale at read time: 

// Typed path — in-process Go reader holding *audit.AuditEvent.
audit.RenderLabels(ev, deps.Translator, configuration.LangPTBR)
//   ev.Changes[0].FieldLabelKey == ""        (popped)
//   ev.Changes[0].FieldLabel    == "CEP"     (rendered)
//   ev.Children["Address"][0].Changes[0].FieldLabel == "CEP"

// JSON path — BI / SQL tools parsing the audit_events.jsonb payload as map[string]any.
var doc map[string]any
_ = json.Unmarshal(jsonbBytes, &doc)
audit.RenderLabelsInJSON(doc, deps.Translator, configuration.LangPTBR)
//   doc["changes"][0]["fieldLabel"]    == "CEP"
//   doc["changes"][0]["fieldLabelKey"] is deleted

Both renderers mutate in place and walk the same shape — top-level changes plus children.<typeName>[].changes; snapshot blocks are untouched. Catalog miss inherits the Translator.Render fallback: the raw key reaches fieldLabel and a slog.Warn("translation.key.missing", …) fires once per (lang, key) tuple.

Caveats: FindByID issues a multi-partition index scan (composite PK (id, created_at)) — fast for recent rows, costlier into archived partitions (narrow it with created_at via a bespoke query through the engine's Querier when the lookup goes deep). FindByAggregate returns every matching row; long timelines should slice downstream or run a bespoke query with explicit LIMIT/OFFSET. The JSON round-trip yields float64/string/bool/map/slice — assert on stringified values, not Go-typed scalars.

ELK / SQL consumption — reconstructing a timeline

Both destinations expose the same vocabulary, so a timeline of one aggregate reconstructs identically from either side: 

# ELK / Loki — query the slog wire fields:
entityType:User AND entityId:<uuid>   sorted by dateTime ASC

-- Relational store — query the authoritative row directly (joinable to other SQL state):
SELECT verb, action_name, kind, actor, occurred_at, payload
FROM audit_events
WHERE entity_type = 'User' AND aggregate_id = '<uuid>'
ORDER BY occurred_at ASC;

The threadId on every event ties an audit row to the related integration event and request log lines (both tables carry it) — the cross-reference is by threadId, never by widening the audit schema with foreign payloads. Audit is "data-write forensics"; integration events are "cross-service emission" — two contracts kept deliberately separate.
