Authorization

Authentication is solved by AuthMiddleware populating AppContext.Identity from the verified JWT. Authorization — what the authenticated principal is allowed to do — travels through three concentric layers, each with its own surface. All three consume AppContext.Identity() and surface rejections through the canonical envelope with HTTP 403. The framework does NOT enforce identity at the infra layer.

Layer 1 — declarative gate via RequirePermission

The single canonical way to gate a route on a permission. The same option covers the three route registration paths (canonical via *Spec siblings, manual-with-pipeline with hand-rolled RouteSpec, raw via MountRaw):

// Canonical
fwopenapi.Mount(d.OpenAPIRegistry, users, fiber.MethodPost, "/",
    insertH, insertSpec,
    fwopenapi.Doc{Summary: "Create a user", Tags: tags},
    fwopenapi.RequirePermission("users:write"))

// Raw (free-form / vendor-shaped handlers)
fwopenapi.MountRaw(d.OpenAPIRegistry, app, fiber.MethodGet, "/whoami",
    whoamiHandler,
    fwopenapi.RawSpec{Summary: "Whoami", Tags: tags},
    fwopenapi.RequirePermission("users:profile:read"))

On receiving the option, Mount/MountRaw patches spec.RequiredPermission AND wraps the handler with the framework's permission gate which short-circuits with the canonical 403 envelope carrying MissingPermissionNotification when Identity.HasPermission(p) returns false. The OpenAPI generator appends **Required permission:** `<p>` to the description ONLY when the runtime gate is actually enforcing (auth.mode: jwt AND auth.authorization.enabled: true) — under disabled or jwt-without-authz the value stays on spec.RequiredPermission for introspection (codegen, contract diffs), but the description suffix is suppressed so the spec never advertises a constraint the server is not honoring.

The 403 entry is auto-emitted in /openapi.json on every non-public route when auth.mode: jwt is in effect, independent of whether RequirePermission is declared — any authenticated route can produce a Forbidden outcome via Layer 2 or Layer 3.

Permission string format: resource:action (Auth0 / AWS / Stripe convention). The IdP emits a permissions claim carrying an array of strings; Identity.HasPermission(p) matches with three rules:

Claim entryMatches request
users:readexactly users:read
users:*any users:<anything>
*:*any request (super-admin)

Wildcards on the caller side panic at runtime. ctx.Identity().HasPermission("users:*") is a programming bug — the claim wildcards; the route declares the exact action. Compose "any of A or B" with explicit OR over concrete actions.

Master switch — auth.authorization.enabled. Default false. When false, the runtime gate no-ops (handlers run regardless of RequirePermission) AND the spec's **Required permission:** `<p>` description suffix is suppressed — so the documentation never advertises a constraint the server is not honoring. The value stays on spec.RequiredPermission for introspection (codegen, contract diffs), and the 403 auto-emission still applies whenever auth is on. Flipping the YAML to true turns on both enforcement AND the description suffix together, so spec and runtime stay in sync.

Boot-time enforcement. When authorization.enabled: true, bootstrap scans the Registry AFTER Wiring.BeforeServe and BEFORE openapi.Register — every non-public route MUST declare RequirePermission(...), else the boot panics with the offender list. A parallel scanRouteRegistration runs whenever Wiring.OpenAPI != nil (independent of authz) and panics on any Fiber route registered outside Mount/MountRaw — the canonical channel is structural to the framework.

Layer 2 — programmatic rule in BuildRules

Rules that depend on the specific resource state, the principal's claims, or the relationship between them. Anything Layer 1's static "needs permission X" cannot express ("only the owner can archive", "cannot delete the last admin", "email cannot change after activation unless admin").

Every write verb routes through domain.GetXxx → BuildRules BEFORE the SQL fires. The actionName parameter tells the entity which verb is firing ("GetInsertable" / "GetUpdatable" / "GetPartialUpdatable" / "GetArchivable" / "GetUnarchivable" / "GetDeletable"); the rule body branches on it. The identity-derived value reaches the entity via the Command's mapper — the canonical place to translate ctx.Identity() into business-named runtime-only fields (not declared in the TableSchema).

// Command mapper — application layer, the only layer that may translate ctx
// into business-named entity fields. Runtime-only fields are simply not declared
// in the TableSchema, so the persister never persists or scans them.
func (*ArchiveUserCommand) ApplyTo(ctx *configuration.AppContext, u *User) error {
    if id := ctx.Identity(); id != nil {
        if email, _ := id.Claims["email"].(string); email != "" {
            u.RequestingPrincipalEmail = email
        }
        u.RequestingPrincipalIsAdmin = id.HasPermission("users:admin")
    }
    return nil
}

// BuildRules — domain layer, branches by actionName to scope the check
// to specific verbs. Notification carries SemanticForbidden → 403.
func (u *User) BuildRules(actionName string, svc domain.Service, r *domain.Rules) {
    r.IfUpdate(func() {
        if actionName == "GetArchivable" && u.RequestingPrincipalEmail != "" {
            if u.Email != u.RequestingPrincipalEmail && !u.RequestingPrincipalIsAdmin {
                r.AddNotification("ID", domain.ArchiveNotAllowedNotification{})
            }
        }
    })
}

Layer 3 — tenant scoping (cross-cutting)

Multi-tenant isolation — a principal in tenant A cannot see or modify resources of tenant B. Three pieces, all wired by the same yaml block:

  • Claim presence gate at the middleware (auth.authorization.tenant.required: true) — after JWT validation succeeds, AuthMiddleware rejects any non-public request whose Identity.TenantID() returns empty, with TenantMissingNotification (403) before any handler runs. Uniform across the service.
  • Reads — Query.ToCriteria(ctx) injects crit.Filter["tenant_id"] = ctx.Identity().TenantID(). When the middleware gate is on, the value is guaranteed non-empty.
  • Writes — the Command's mapper populates entity.TenantID; BuildRules enforces that the resource's TenantID matches the principal's claim, emitting TenantMismatchNotification (403) on mismatch.
func (q *FindUserByParamsQuery) ToCriteria(ctx *configuration.AppContext) (fwqueries.ReadCriteria, error) {
    crit := q.WireCriteria
    if t := ctx.Identity().TenantID(); t != "" {
        crit.Filter["tenant_id"] = t
    }
    return crit, nil
}

Field-level read access — ReadCriteria.Restrict

Layers 1–3 gate rows and operations; Restrict gates columns on the read. A Query calls it inside ToCriteria(ctx), after deciding from the identity that the caller may not see a field, to remove that field from the read entirely — it is not projected, sorted by, or filtered on. Because the tabular export prunes its column plan to the same effective projection, the field drops from the JSON and the CSV/XLSX (header included), so ToCriteria is the single source of truth across every format. 

func (q FindUserByParamsQuery) ToCriteria(ctx *configuration.AppContext) (fwqueries.ReadCriteria, error) {
    crit := q.Criteria
    if id := ctx.Identity(); id == nil || !id.HasPermission("users:admin") {
        if err := crit.Restrict("Salary"); err != nil {
            return crit, err   // 403 when the request actively asked for the field
        }
    }
    return crit, nil
}

Two outcomes by intent: a passive read (the field simply not requested) gets the silent omission; an active reference — a ?sort=, ?filters=, or explicit ?fields= on the restricted field — returns a 403 FieldAccessForbiddenNotification. Refusing the active attempt is more honest than silently ignoring the knob, and it closes the inference leak a dropped sort/filter would otherwise leave. The decision lives in the application layer (the Query reads Identity); infra never sees it.

YAML configuration

auth:
  mode: jwt
  jwt: { issuer: ..., audience: ..., jwksUrl: ... }
  publicRoutes: [GET /health]
  authorization:                  # default nil (off; identity helpers still work)
    enabled: true                 # master switch — when false, runtime gate no-ops
    permissionsClaim: permissions # default "permissions"
    tenant:
      enabled: false              # default false
      claim: tenant_id            # default "tenant_id"
      required: false             # true → middleware rejects empty TenantID with 403

Strict YAML decoding on authorization + tenant. Unknown keys (e.g. permissionClaim typo) abort the boot with a diagnostic naming the offending key.

Identity helpers

func (i *Identity) HasPermission(p string) bool
func (i *Identity) TenantID() string

Both are nil-safe. HasPermission tolerates multiple claim shapes ([]string, []any, space-separated, comma-separated); panics on caller-side wildcards. TenantID tolerates string, []string{one}, []any{one} shapes; anything else returns "". The parsed permissions set is cached on the Identity after the first call.

Why defense-in-depth at infra is deliberately absent

Postgres.Insert/Update/Archive/Unarchive/Delete and MongoViewReader.ReadPage/ReadByID execute what the application layer validated; they do not pronounce identity. Adding a scope-filter knob to the TableSchema would force the infra adapters to know domain concepts (tenant, owner, role) — violating the dependency ruler and creating two sources of truth for the same rule. A bug bypassing BuildRules or ToCriteria(ctx) is a domain/application bug, fixed at that layer — not papered over by infra duplication.
