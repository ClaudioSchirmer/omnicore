Service-to-service communication

Four infrastructure surfaces carry traffic across service boundaries. The choice is driven by temporal coupling — whether the caller must block on the answer — not by which call is most convenient to write. Pick the mechanism by the question you are actually answering; the framework exposes exactly one canonical path for each.

I need to… Use Why
Get an answer now and my response to the caller depends on it httpclient (sync) The temporal coupling is inherent — there is no answer to give until the other service replies. Request/response over the per-service registry (breaker, pool, TLS, auth, cache).
Read another service's state inside my own queries UpstreamSubscription + FromMongo (read-side) You do not need a call — you need the data local. The framework materializes the upstream collection from its event stream and ripples recompose into every view that embeds it. Reads never leave the process. See the cross-service composition example.
Signal that something happened so other services can react integration events (async) Decouple in time: emit a typed event into integration_events (atomic with the data write) and let subscribers consume it on their own clock. No blocking, no fan-out coupling in the producer.
Send a command to another service with no return value (rare) ↳ reformulate as an integration event There is no separate fire-and-forget primitive, by design. A subscriber's Receiver.On runs the same pipeline.Handler an HTTP route would, and the event DTO carries ToCommand() — so "command without return" is "event + reaction". Modeling it as an event keeps the producer decoupled from the consumer's command surface.

The read-side path and the event path share one spine. FromMongo is not a parallel universe to integration events — the upstream collection it reads is itself materialized by the framework consuming an event stream. "Read another service's state" and "react to another service's event" are two consumer-facing surfaces over the same CDC backbone; the difference is whether you want the data projected locally or a handler invoked.

Cache is orthogonal to all four — a cross-cutting accelerator for the sync path (httpclient response cache) and read amplification, never a transport in its own right.
