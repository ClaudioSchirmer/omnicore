In-TX side effects via lifecycle hooks

The framework exposes two lifecycle slots on every write verb (Insert / Update / Archive / Unarchive / Delete) — both fire INSIDE the persister's TX, so a hook can write companion rows, denormalizations, or extra outbox events atomically with the framework's own writes. The names anchor on the TX verbs themselves so the consumer reads the trigger directly:

SlotPositionUse case
afterBeginINSIDE the TX, BEFORE any framework write (data + outbox + audit)Acquire an advisory lock; consult adjacent state under serializable isolation; enforce a cross-aggregate precondition the data write itself depends on.
beforeCommitINSIDE the TX, AFTER all framework writes, BEFORE COMMITEmit an extra outbox row with a different event_type; write a denormalization row; perform a cross-table read-then-write that needs the post-write state of the aggregate.

A non-nil error returned by either slot rolls back the entire TX. domain.NotificationCarrier identity is preserved end-to-end — a typed notification returned from the hook reaches the wire envelope verbatim, at the notification's own HTTP status. A panic inside the hook propagates through pipeline.Run's defer/recover and renders as 500; defer tx.Rollback() fires automatically.

The persister always emits a slog.Warn("persistence.hook.error", verb, hookSlot, entityType, threadId, error) line on every hook error as a best-effort observability echo; the line is non-blocking, so a slog handler failure never masks the rollback.

Auto handler path (declarative — methods on the Cmd)

The Cmd opts in by declaring an AfterBegin and/or BeforeCommit method matching the provider interface for the consumer's entity type. The Auto Command Handler detects each via type assertion at the top of Handle and forwards the method values as WriteOption[T] closures to the repo.Scope(ctx, opts...) binding, then calls the resulting pure domain.Writer (e.g. .Insert(valid)). 

// application/commands/insert_user.go
type InsertUserCommand struct {
    pipeline.CommandWithBodyBase
    Name  string
    Email string
}

func (c *InsertUserCommand) ToEntity(_ *configuration.AppContext) (*User, error) {
    return &User{Name: c.Name, Email: c.Email}, nil
}
func (c *InsertUserCommand) FromEntity(_ *configuration.AppContext, u *User) (InsertUserResult, error) {
    return InsertUserResult{ID: *u.GetID(), Name: u.Name, Email: u.Email}, nil
}

// Optional in-TX side effect: emit an extra integration-event row
// atomically with the framework's data write + outbox row + audit row.
//
// TxHandle is a sealed marker — it carries no public methods. The Cmd
// cannot pronounce SQL through it. The canonical (and only) shape is a
// port declared in application/ (or domain/) whose method receives a
// persistence.TxHandle; the port's adapter in infra/ calls
// core.UnwrapTx(tx) to recover the backend-neutral core.Tx
// (Exec/Query/QueryRow + Dialect()) and owns the SQL + table name. The
// hook is just the composition point.
func (c *InsertUserCommand) BeforeCommit(
    ctx *configuration.AppContext, u *User, id domain.ID, tx persistence.TxHandle,
) error {
    // c.NotificationOutbox is a port injected on the Cmd; its adapter in
    // infra/ owns the SQL emitting the companion integration event
    // atomically with the framework's data + outbox + audit rows.
    return c.NotificationOutbox.EnqueueActivationRequested(ctx, tx, id)
}

// Recommended compile-time safety against typos in the method name.
var _ persistence.BeforeCommitHookProvider[*User] = (*InsertUserCommand)(nil)

Manual handler path (closure passed at the call site)

The same persister surface serves the manual path — the closure is supplied directly via persistence.WithAfterBegin[T](fn) / persistence.WithBeforeCommit[T](fn) as trailing options on the repo.Scope(ctx, opts...).Method(valid) binding. There is one canonical persister surface; Auto and manual differ only in how the closures originate (Cmd method vs explicit closure).

Application stays SQL-free on the manual path too — persistence.TxHandle is a sealed marker with no public methods, so the closure cannot pronounce SQL through it by construction. The canonical shape is a port declared in application/ (or domain/) whose method receives a persistence.TxHandle; the port's adapter in infra/ calls core.UnwrapTx(tx) to recover the backend-neutral core.Tx (render SQL via its Dialect(), run via Exec/Query/QueryRow) and owns the SQL + table name. The closure threads tx through the port so the side effect remains atomic with the framework's writes, on every supported engine alike. 

func (h *CreateUserAdminHandler) Handle(
    ctx *configuration.AppContext, cmd *AdminCreateUserCommand,
) (Result, error) {
    user := buildUser(cmd)
    insertable, err := domain.GetInsertable(user, h.svc, "AdminCreate")
    if err != nil { return Result{}, err }

    id, err := h.repo.Scope(ctx,
        persistence.WithBeforeCommit[*User](func(
            ctx *configuration.AppContext, u *User, id domain.ID, tx persistence.TxHandle,
        ) error {
            // h.NotificationOutbox is a port injected on the handler; its
            // adapter in infra/ owns the SQL emitting the companion
            // integration event atomically with the framework's data +
            // outbox + audit rows. The adapter calls core.UnwrapTx(tx)
            // to obtain the backend-neutral core.Tx; the handler imports
            // no driver.
            return h.NotificationOutbox.EnqueueAdminUserActivated(ctx, tx, id)
        }),
    ).Insert(insertable)
    if err != nil { return Result{}, err }
    return Result{ID: id}, nil
}

TxHandle — sealed marker

Hooks receive the framework's TX as persistence.TxHandle — a sealed interface with no public methods. The single sealing method on it is unexported, so the only implementations are the framework's own engine handles (Postgres's pgxTxHandle, MySQL's mysqlTxHandle, SQL Server's sqlserverTxHandle), each carrying the live driver transaction privately. Application code cannot read or write SQL through the handle by construction.

The canonical (and only) shape for an in-TX side effect from a hook:

  1. Declare a port in application/ (or domain/) — a pure Go interface whose method receives a persistence.TxHandle parameter.
  2. Implement the port in infra/ — the adapter calls core.UnwrapTx(tx) core.Tx to recover the backend-neutral transaction and owns the SQL + table name. core.Tx renders SQL per backend via its Dialect() and runs it via Exec/Query/QueryRow, so the adapter is engine-agnostic (any supported engine). UnwrapTx lives in infra/db/core, so only adapters in the infra layer can call it.
  3. Inject the port on the Cmd (or manual handler) and call it from the hook closure. The framework's TX is honored end-to-end; the application layer never pronounces SQL.

UnwrapTx panics with a descriptive diagnostic if passed a foreign TxHandle implementation — defensive, never reached against framework-issued handles because the interface is sealed. Constraint-binding translation (write.ConstraintBinding) is not applied at this surface — it lives at the Repository level for the parent entity's declared constraints.

Postgres-only escape hatch. A service that deliberately pins itself to Postgres — to reach an advanced pgx feature such as CopyFrom, SendBatch or Prepare — may call postgres.UnwrapPgxTx(tx) pgx.Tx instead, recovering the live pgx.Tx. This couples the adapter to Postgres (a mysql-tagged build will not link postgres), so reach for it only when the neutral core.Tx genuinely cannot express the operation; the default remains core.UnwrapTx.

Aggregate-path symmetry

Both persister paths — flat (non-aggregate entities) and aggregate (entities implementing AggregateRootProvider) — fire the hooks at the same analogous positions, with the same generic signature, the same firing cardinality (single firing per repo.Method() call, granularity B, matching outbox and audit row cardinality). The hook receives the root entity with all aggregate children reachable via the usual domain.GetCurrentItemsOf[VO] helpers. Consumer code does not know which dispatch path the persister took.
