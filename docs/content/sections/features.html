What the framework does

Importing the module gives a service the full DDD + CQRS spine — typed validation, atomic persistence with outbox, guaranteed audit, multi-language, structured logging, the CQRS pipeline, and standardized REST and GraphQL surfaces. This page is a map: each capability links to the section that documents it in depth. The dedicated sections are the source of truth — start here, then dive in.

Domain — pure business rules

  • Rules DSL — IfInsert/IfUpdate/IfDelete/IfInsertOrUpdate mode-scoped validation on the entity
  • Aggregate persistence — AggregateRoot with status tracking + type-guarded child primitives; AggregateRootProvider opts into atomic aggregate-aware persistence and child auto-validation
  • Old-state snapshot — pre-mutation entity available to BuildRules and the auditor
  • Typed notification system — translation key = struct name; NotificationKey + Semantic carried to the wire

Application — pipeline & ports

  • CommandHandler / QueryHandler — the Pipeline dispatcher with exception/panic capture and generic Result[T] (Success/Failure/Exception)
  • Auto command + auto query handlers — generic CRUD with zero handler code
  • AppContext — UUID + Language + Identity per request
  • Translator — 7 built-in catalogs (PT-BR / ENG / ES / FR / DE / IT / NL)
  • ScopedRepository[T] + lifecycle hooks — reads stay direct on the handle; writes bind ctx + actor + the in-TX afterBegin / beforeCommit hooks via Scope

Infrastructure — persistence & sync

  • TableSchema — one explicit Go-field↔column map driving PG write + criteria + scan + the Mongo view
  • Atomic outbox + transparent aggregate persistence — one transaction covers root + children + a single outbox row
  • Audit pipeline — every write emits an AuditEvent routed by audit.destinations (in-TX audit_events row and/or post-commit slog echo)
  • SyncEngine + Composer — Kafka consumer materializes Mongo views from the outbox; Mongo mirrors PostgreSQL (archived rows survive unless DeleteOnArchive())
  • UpstreamSubscriber — materializes upstream events into a local Mongo collection and ripples recompose to every embedding view
  • Cache · httpclient · integration events — the cross-service plumbing

Web — REST, GraphQL & export

  • Canonical envelope + HTTP status mapping — RespondFromResult[T] derives the status from each notification's transport-agnostic Semantic()
  • Query wrappers — allowlist via query:/filter: tags, keyset pagination, sparse ?fields=, sort; path: tag for universal URL-segment binding
  • Tabular export — HandleQueryAsCSV / HandleQueryAsXLSX attach the SAME query handler to a downloadable CSV or Excel file (hierarchical, labelKey headers, ?fields=-narrowed, capped at query.maxExportRows)
  • OpenAPI 3.1 + Swagger UI — generated by reflection over your Go DTOs, no codegen
  • GraphQL — the same application handlers behind a single POST /graphql; SDL, Relay connections, and where filters reflected from the same DTOs. Its own web surface, never in the Swagger document
  • JWT auth + 3-layer authorization — middleware validation + permission gate + tenant scoping, shared across REST and GraphQL
