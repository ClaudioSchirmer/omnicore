What the framework does

Import the module and a service inherits the whole DDD + CQRS spine. You write the domain — the framework wires the transactional write side, the Mongo-projected read side, and every transport surface from one microservice.<profile>.yaml and a single Wire function. Write it once — attach it anywhere

A handler — command (write) or query (read) — is a pure pipeline.Handler[TReq, TRes] that never learns which surface invoked it. The surface decides only the I/O shape.

Everything below the boundary is identical: on writes, BuildRules validation, the sealed ValidEntity, the transactional outbox and the audit row; on reads, the ToCriteria overlays, the filter allowlist and keyset pagination. Serve a new channel by attaching the same instance to another wrapper — never by rewriting logic. See handler invariance →

Model your domain
Pure business rules — zero IO, enforced by the compiler.
  • Rules DSL — IfInsert/IfUpdate/IfDelete/IfArchive/IfUnarchive/IfInsertOrUpdate mode-scoped validation, propagated through aggregate children
  • Aggregate root + value objects — root and its 1:N children are one boundary; Archive/Unarchive/Delete cascade symmetrically
  • Old-state snapshot — domain.Old[T]() exposes the pre-write entity to BuildRules and the auditor
  • Typed notifications — struct name is the translation key; NotificationKey + Semantic ride to the wire
  • Sealed ValidEntity — Insertable/Updatable/Archivable/… produced only by domain

Persist atomically
One transaction covers data, outbox and audit — always.
  • Six write verbs, zero handler code — insert, update, partial-update, archive, unarchive, delete
  • TableSchema — one explicit Go-field↔column map turns a flat domain entity into a normalized (3NF) physical layout
  • One transaction — data rows + a single outbox row + the audit row commit together
  • Lifecycle hooks — in-TX AfterBegin / BeforeCommit side effects, once per operation
  • Guaranteed audit — one event per write; snapshot / delta / transition bodies; database + slog routing
  • Manual command handler — same envelope, notifications and audit; full wiring control

Read at scale — CQRS
Eventually-consistent Mongo projections, mirrored from the write side.
  • Auto query handlers — allowlisted filters, keyset pagination, sparse ?fields=, ?orderBy=, only-total
  • 16 filter operators — eq/ne/in/gte/startsWith/contains… plus case-insensitive variants, allowlisted per field by tag
  • Computed read fields — a wire field with no column, derived once by the Query's FromQueryResult and rendered identically by every surface; its sources are pushed down to the store
  • SyncEngine + composer — outbox → CDC relay → the transport (Kafka/NATS) materializes views; archived rows survive unless DeleteOnArchive()
  • ComposedView / SharedBaseView — read-time joins and all-in-one identity, never materialized on the request path
  • CSV / XLSX export — the same query handler streamed to a file, hierarchical, translated headers
  • Manual query handler — bespoke parsing and envelopes over the same reader

One handler, every surface
Attach a handler to a surface — never rewrite it.
  • REST + canonical envelope — each notification's Semantic() derives the HTTP status; no status codes in handlers
  • OpenAPI 3.1 + Swagger UI — reflected from your Go DTOs, no codegen, no annotations
  • GraphQL — own surface, Relay connections, per-field authz, schema reflected from the same DTOs
  • gRPC (Connect) — dedicated listener; pb↔DTO bridge boot-checked; google.rpc error details; internal-plane posture
  • Integration events — async facts; at-least-once, idempotent consumers, retry surface
  • Handler invariance — the same instance drives all of the above

Secure every request
Identity in, authorization enforced — one JWT core, every transport.
  • AppContext — UUID + language + Identity per request; implements context.Context; owns cancellation
  • JWT authentication — JWKS / PEM / external validator, revocation cache, expired-vs-invalid split
  • 3-layer authorization — permission gate (resource:action) · BuildRules · tenant scoping
  • Field-level read control — Restrict gates columns; 403 on an active reference, silent omission otherwise
  • Shared authcore — one validation core behind the REST and gRPC shells

Talk to other services
One canonical channel per question — no accidental coupling.
  • The channel decision matrix — sync internal → gRPC, sync external → HTTP, async facts → events, async views → composition
  • httpclient — outbound HTTP from YAML: retry, cache, breaker, idempotency, TLS, HMAC, OAuth2, streaming
  • grpcclient — outbound gRPC toolbox; retry/breaker/backoff cores shared with httpclient
  • Upstream composition — UpstreamSubscription / JoinUpstream, ripple recompose, failure registry
  • Integration events — typed Dispatch / Receiver, best-effort dedup, operator retry surface
