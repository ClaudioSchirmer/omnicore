Authentication middleware

When auth.mode: jwt in microservice.<profile>.yaml, bootstrap.Run auto-registers fwweb.AuthMiddleware right after AppContextMiddleware. Every request is validated end-to-end before it reaches a Feature route; on success the middleware populates AppContext.Identity. When auth.mode: disabled, the middleware is not registered at all — there is no runtime cost and Identity() stays nil.

Validation flow

  1. publicRoutes bypass. Exact METHOD /path match against auth.publicRoutes — health/ready probes, login endpoints, anything else the service declares. Match → request proceeds without auth.
  2. Bearer extraction. Reads Authorization: Bearer <token> (scheme match is case-insensitive). Empty or malformed → MissingAuthorizationNotification, 401.
  3. Local JWT validation. Signature verified against jwksUrl (preferred, supports rotation via MicahParks/keyfunc) or publicKeyPem (RSA/ECDSA/Ed25519 in SubjectPublicKeyInfo form). The alg header must be in the configured allowlist (default RS256, ES256, EdDSA); iss must match auth.jwt.issuer; aud must contain auth.jwt.audience; exp must be in the future after applying leewaySeconds.
  4. Identity attachment. On success, AppContext.SetIdentity attaches a *Identity carrying Subject/Issuer/ExpiresAt and a copy of the raw claim map (so handler mutations cannot leak back). The middleware also calls AppContext.SetBearerToken(token) with the verified raw JWT — consumed exclusively by the forward-bearer httpclient auth provider. Handlers should keep reading Identity() for principal data; BearerToken() is for downstream credential propagation, not for parsed claim access.

Error responses

Failures use the same response envelope as other framework rejections, translated to the request's Accept-Language, with Semantic = Unauthorized → 401:

ScenarioNotificationKey
No Authorization header, or header doesn't match Bearer <token>MissingAuthorizationNotification
Token malformed, signature mismatch, wrong iss/aud, disallowed algInvalidTokenNotification
Token exp in the past (after leeway)ExpiredTokenNotification

Expired is split from Invalid so clients can branch on refreshing the token vs. re-authenticating from scratch.

External validator (revocation check)

When auth.externalValidator is set, the middleware adds one more step after local validation passes: an outbound HTTP call to the IdP (RFC 7662 introspection endpoint or any compatible API). This catches revoked tokens — a JWT that locally still has a valid signature and an unexpired exp claim can already be revoked at the IdP, and only the IdP knows.

Cache is opt-in, default off. Set cacheTtlSeconds to a positive integer to enable an in-memory positive-only cache keyed by the SHA-256 hash of the bearer token (the raw token is never stored). Only successful validator answers are memoized — negative answers and transport errors deliberately bypass the cache so a revocation is honored on the very next request. The trade-off: tokens that were already cached as valid can keep passing for up to TTL seconds after they get revoked at the IdP. Default 0 disables the cache entirely and every authenticated request calls the IdP.

Token placement

The token is carried in the outgoing request according to tokenPlacement:

PlacementShapeTypical use
bearer_headerAuthorization: Bearer <token>Auth0, custom resource-server APIs
form_fieldapplication/x-www-form-urlencoded body, tokenField=<token>Keycloak introspection (RFC 7662)
json_bodyapplication/json body, {"<tokenField>": "<token>"}Custom JSON APIs
query_paramURL query, ?<tokenField>=<token>Legacy query-string APIs

Success check

The response body is parsed as JSON, then success.jsonPath (dot notation, e.g. $.active or $.data.is_active) is matched against success.expectedValue. Equality is Go's == on any: types and values must both match (true != "true"). Path not found, type mismatch, or value mismatch → reject (401 InvalidTokenNotification).

Fail mode

failMode: closed (default) rejects the request on any validator-side error — transport failure, timeout, non-2xx status, malformed body. Safer: a token whose validity cannot be confirmed is not honored.

failMode: open swallows transport-level errors when the local pre-validation already passed — useful when the IdP is operationally fragile and you prefer availability over instant revocation. Explicit "not active" answers still reject under failMode: open; only ambiguous validator errors are suppressed.

Audit log carries the actor

Every AuditEvent emitted by the framework — both the audit_events row written in-TX by the database destination and the slog line emitted post-commit by the slog destination — includes the authenticated principal of the request: Subject (JWT sub), Issuer (JWT iss), and an opt-in subset of custom Claims (tenant_id, roles, etc.) declared in auth.auditClaims. Anonymous requests (auth disabled, public route, background job) surface as actor: "anonymous" in the slog line and as NULL in the row's actor column (the partial index audit_events_actor_idx excludes them so identified-actor queries stay on a narrow path).

// Audit line shape
{
  "msg": "audit",
  "threadId": "5f25...",
  "actor": "user-42",                    // JWT sub (or "anonymous")
  "actorIssuer": "https://idp.example",  // JWT iss (omitted when empty)
  "actorClaims": {                       // omitted when allowlist is empty or no claim matched
    "tenant_id": "acme",
    "roles": ["admin"]
  },
  "entityType": "User",
  "entityId": "abc-123",
  "verb": "insert",
  "actionName": "GetInsertable",
  "kind": "snapshot",
  "dateTime": "2026-06-09T12:00:00Z",
  "snapshot": { "name": "Jane Doe", "email": "jane@x.test" },
  "children": { "Address": [{ "id": "...", "op": "inserted", "snapshot": {...} }] }
}

The fan-out is automatic for both Auto Command Handlers and manual handlers — every write goes through repo.Scope(ctx, opts...).Method(valid) on the persistence.ScopedRepository[T] binding, and ctx IS the request *AppContext. infra.Postgres reads the actor from the same context, builds the AuditEvent, writes the row in-TX, and emits the slog line post-commit. A manual handler does not need to touch any new API to benefit from the actor information.

Domain events emitted via infra/events.SlogPublisher mirror the same pattern (actor + actorIssuer) but never carry actorClaims — the audit allowlist is the only place that can broaden the claim surface logged, by design.

Token issuance

The framework only validates — it does not mint tokens. The IdP (Keycloak, Auth0, an in-house auth service, etc.) issues tokens; each service consumes them. Login endpoints, refresh, and credential storage live in the IdP or in a dedicated auth service.
