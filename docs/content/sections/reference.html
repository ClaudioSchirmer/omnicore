Error helpers

Each layer exposes 1-liner helpers that return the layer's typed error:

LayerHelperReturns
domainSingleNotificationError / NotFoundError / FieldErrorWithCause*DomainError
infraSingleNotificationError / FieldErrorWithCause*InfrastructureError
application/exceptionSingleNotificationError / FieldErrorWithCause*ApplicationError

ApplicationError lives in omnicore/application/exception/ (previously in pipeline/exception.go).

Invariants

  1. ValidEntity is only constructed by the domain package — unexported entity() method.
  2. Outbox always in the same SQL transaction — guaranteed by infra.Postgres.
  3. Audit always runs at the persister — every Postgres.Insert/Update/Archive/Unarchive/Delete emits the configured destinations (in-TX audit_events row + post-commit slog echo).
  4. Lifecycle hooks fire INSIDE the TX — afterBegin at position A (before any framework write); beforeCommit at position D (after data + outbox + audit, before COMMIT). Single firing per repo.Method() call regardless of aggregate child count. Non-nil error rolls everything back; NotificationCarrier identity reaches the wire envelope verbatim.
  5. Notifications are typed structs, never strings.
  6. Domain has no IO — only types, validation, rules.
  7. NotificationCarrier is the cross-layer contract for errors.
  8. Kernel notifications embed the base of the correct layer (Domain/Application/Infrastructure).
