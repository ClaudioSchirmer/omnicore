Custom command handler

The Auto command handlers hide every wiring step behind a one-line generic handler. This page builds the same write from scratch — a hand-written pipeline.Handler and explicit route wiring — and names the facilitator the framework offers at each step. It is the escape hatch for wiring control (alternative identifiers, cross-service IO, injected domain services, bespoke orchestration), not a lesser tier: the same domain layer, pipeline, atomic outbox, audit, and notification translation apply, byte-for-byte identical to the canonical path.

Every step below maps onto the full flow of a POST. For a complete runnable reference, see omnicore-example-users/web/user_custom_routes.go and the hand-written handlers under application/commands/handlers/*_custom_handler.go.

Full example

1. Define the domain entity

// internal/domain/customer.go
package domain

import (
    "github.com/ClaudioSchirmer/omnicore/domain"
)

type Customer struct {
    domain.BaseEntity
    Name  string `json:"name"`
    Email string `json:"email"`
}

// Include only the modes this entity supports. Missing modes are
// blocked by the framework with *NotAllowedNotification (403):
//   ModeDisplay   — read
//   ModeInsert    — create
//   ModeUpdate    — field mutation
//   ModeDelete    — hard delete
//   ModeArchive   — soft delete (state transition)
//   ModeUnarchive — restoration (state transition)
// Append-only: declare only Display + Insert. Archiving an entity without
// ModeArchive in Modes() responds with ArchiveNotAllowedNotification.
func (c *Customer) Modes() []domain.EntityMode {
    return []domain.EntityMode{
        domain.ModeDisplay, domain.ModeInsert, domain.ModeUpdate, domain.ModeDelete,
        domain.ModeArchive, domain.ModeUnarchive,
    }
}

// RequiresService omitted — inherits default `false` from *BaseEntity (via embed).
// Declare only if the entity needs domain.Service in BuildRules
// (e.g., cross-entity lookups), returning true.

// NO TableName/ToFields. Infra maps the entity via an explicit TableSchema
// (NewTableSchema[*Customer]("customers").Field("Name","name")...), threaded
// onto the Repository with WithSchema — no name inference.

func (c *Customer) BuildRules(actionName string, service domain.Service, r *domain.Rules) {
    r.IfInsertOrUpdate(func() {
        if c.Name == "" {
            r.AddNotification("Name", domain.RequiredFieldNotification{})
        }
        if c.Email == "" {
            r.AddNotification("Email", domain.RequiredFieldNotification{})
        } else if !validEmail(c.Email) {
            // optional value becomes FieldValue — echo of rejected input in the response
            r.AddNotification("Email", InvalidEmailNotification{}, c.Email)
        }
    })
}

2. Implement the Repository

// internal/repository/customer_repo.go
package repository

import (
    "context"

    "github.com/ClaudioSchirmer/omnicore/domain"
    "github.com/ClaudioSchirmer/omnicore/infra"
    "github.com/ClaudioSchirmer/omnicore/infra/criteria"
)

// Embed BaseRepository[*Customer] to inherit Scope(ctx, opts...) →
// Insert/Update/Archive/Unarchive/Delete and New() — no hand-written writes.
// The writes route through infra.Postgres with the atomic outbox preserved;
// the Go↔column map is declared once via WithSchema (no name inference).
type CustomerRepo struct {
    infra.BaseRepository[*Customer]
    loader *infra.AggregateLoader[*Customer]   // for FindByID
}

func NewCustomerRepo(pg *infra.Postgres) *CustomerRepo {
    newCustomer := func() *Customer { return &Customer{} }   // single factory source
    schema := CustomerSchema()   // NewTableSchema[*Customer]("customers").PK("id").Field("Name","name")...
    r := &CustomerRepo{
        BaseRepository: infra.BaseRepository[*Customer]{
            Postgres: pg, ContextName: "Customer", NewEntity: newCustomer,
        },
        // The standalone loader needs the schema too: BaseRepository.WithSchema
        // threads only the write binding, not this separate loader field.
        loader: infra.NewAggregateLoader[*Customer](pg, newCustomer).WithSchema(schema),
    }
    r.WithSchema(schema)   // write binding (BaseRepository.Schema)
    return r
}

// FindByID is the service's responsibility — delegate to the loader.
func (r *CustomerRepo) FindByID(id domain.ID) (*Customer, error) {
    return r.loader.FindOne(context.Background(), criteria.ByID(id))
}

3. Define the Command and the Handler

// internal/commands/create_customer.go
package commands

import (
    "github.com/ClaudioSchirmer/omnicore/application/configuration"
    "github.com/ClaudioSchirmer/omnicore/application/persistence"
    "github.com/ClaudioSchirmer/omnicore/application/pipeline"
    "github.com/ClaudioSchirmer/omnicore/domain"
)

type CreateCustomerCommand struct {
    pipeline.CommandBase
    Name  string `json:"name"`
    Email string `json:"email"`
}

type CreateCustomerHandler struct {
    repo persistence.ScopedRepository[*Customer]
}

func NewCreateCustomerHandler(repo persistence.ScopedRepository[*Customer]) *CreateCustomerHandler {
    return &CreateCustomerHandler{repo: repo}
}

func (h *CreateCustomerHandler) Handle(
    ctx *configuration.AppContext,
    cmd CreateCustomerCommand,
) (domain.ID, error) {
    customer := &Customer{Name: cmd.Name, Email: cmd.Email}
    insertable, err := domain.GetInsertable(customer, nil, "GetInsertable")
    if err != nil {
        return domain.ID{}, err
    }
    // Scope binds the request ctx + any in-TX lifecycle hooks (passed as
    // Scope opts) and returns a pure domain.Writer; the domain port never
    // pronounces the ctx.
    return h.repo.Scope(ctx).Insert(insertable)
}

4. Wire the route

// internal/web/router.go
app.Post("/customers", func(c fiber.Ctx) error {
    var cmd commands.CreateCustomerCommand
    if err := c.Bind().Body(&cmd); err != nil {
        return web.RespondWithBadRequest(c)
    }

    appCtx := c.Locals("appCtx").(*configuration.AppContext)
    result := pipeline.Dispatch(pipe, appCtx, cmd, createCustomerHandler)
    return web.RespondFromResult(c, result, fiber.StatusCreated)
})

Manual path (cross-service, side effects)

A handler with external IO, an injected domain service, or multi-step orchestration is just a struct implementing pipeline.Handler[*Cmd, TResult] — the hand-written form this page already showed. TResult is whatever application-layer value the handler returns; the route maps it to the wire TResp via the responseProjection. Wire it either fully by hand (as in step 4 above) or through the canonical HandleCommandWithBody / HandleCommandWithBodyID / HandleCommandByID wrappers — both reach the same pipeline.

In-TX side effects (enqueue an outbox/notification row, touch another aggregate) ride the persistence hooks: pass persistence.WithAfterBegin[T](fn) / persistence.WithBeforeCommit[T](fn) to repo.Scope(ctx, opts...).Insert(valid) — the closures fire inside the same transaction (positions A and D), identical to what the Auto handlers derive from a Cmd's optional AfterBegin / BeforeCommit methods.

Domain events the entity accumulates via RegisterEvent are published post-commit automatically — the persister forwards them through the wired events.Publisher (SlogPublisher by default) on both the Auto and the manual path, so a hand-written handler needs no extra wiring for them to surface for auditing.

BaseRepository[T] — 5 ready-made writes + New() T

The service embeds fwinfra.BaseRepository[T] and gains Insert/Update/Archive/Unarchive/Delete without writing a line — plus New() T, which materializes the constructor of T (consumed by UnarchiveCommandHandler and available for any scenario needing an empty entity). FindByID is the service's responsibility (see AggregateLoader).

type UserRepository struct {
    fwinfra.BaseRepository[*User]
    loader *fwinfra.AggregateLoader[*User]  // for FindByID
}

newUser := func() *User { return &User{} }  // single factory source

base := fwinfra.BaseRepository[*User]{
    Postgres:  pg,
    NewEntity: newUser,                       // mandatory: feeds Repo.New()
    Constraints: map[string]fwinfra.ConstraintBinding{
        "users_email_active_idx": {Notification: EmailAlreadyExistsNotification{}, Field: "email"},
    },
}

NewEntity is mandatory. New() panics with a clear message if nil — it's a configuration bug detected at boot/first call, not in a hot request. The same factory is typically shared with the AggregateLoader to avoid duplication.

ContextName is optional. When empty, derived from the Go type T via reflect (T=*User → "User") — that's the framework's convention. Set explicitly only when you need to customize (e.g., two Repositories over the same entity with distinct names in the notification context).

Unique violations (PG code 23505) are translated into *InfrastructureError carrying the typed notification — no manual mapPGError. Unregistered constraints, codes other than 23505, and non-pgconn.PgError errors return raw.

BaseAggregateRepository[T] — canonical composition

Almost every aggregate-aware Repository has the same shape: BaseRepository[T] (writes) + *AggregateLoader[T] (FindByID/FindArchivedByID). fwinfra.BaseAggregateRepository[T] bundles both and promotes the trivial wrappers — the service no longer declares FindByID and FindArchivedByID manually. The common case fits in 8–10 lines. 

type UserRepository struct {
    fwinfra.BaseAggregateRepository[*User]
}

func NewUserRepository(pg *fwinfra.Postgres) *UserRepository {
    r := &UserRepository{
        BaseAggregateRepository: fwinfra.NewBaseAggregateRepository[*User](
            pg, func() *User { return &User{} },
        ),
    }
    r.Constraints = map[string]fwinfra.ConstraintBinding{
        "users_email_active_idx": {Notification: EmailAlreadyExistsNotification{}, Field: "email"},
    }
    r.WithSchema(UserSchema())   // children come from the schema's .Child(...) declarations
    return r
}

var (
    _ persistence.ScopedRepository[*User] = (*UserRepository)(nil)
    _ domain.ArchivedFinder[*User]        = (*UserRepository)(nil)
)

FindByID and FindArchivedByID come promoted via embed; New() and the 5 writes also come from BaseRepository via embed. WithSchema(schema) declares the TableSchema once and feeds both the write binding and the read loader; child tables come from the schema's .Child(...) declarations. The *AggregateLoader[T] is exposed as a public Loader field — call the manual-scanner escape hatches WithRootScanner / WithChildScanner on it directly when auto-scan does not fit.

When NOT to use it (keep the old pattern of direct embed BaseRepository[T] + carrying *AggregateLoader[T] separately): custom magic pattern where the Loader is not the canonical source of FindByID (e.g., read replica + main, materialized view). Manual and composite coexist — choose per Repository.

AggregateLoader[T] — loading aggregates with the criteria engine

The AggregateLoader loads live domain aggregates (root + children) from PostgreSQL through the entity search engine: you hand it a criteria.Query and it returns the entity ready for a command. Two entry points — FindOne(ctx, *criteria.Query) (one match, or RecordNotFound; more than one is an error) and FindAll(ctx, *criteria.Query) (a slice; children batched). It has its own SQL engine: it builds the SELECT from the columns your TableSchema declares (the same Go↔column map that drives writes) and scans each row straight into the matched struct field — you write neither the SQL nor the scanner. For exotic decoding the auto-scan doesn't cover (JOIN, CASE, COALESCE) there is a manual-scanner escape hatch; both scan modes coexist.

Loading by criteria — FindOne / FindAll

omnicore/infra/criteria is a small, pure DSL (stdlib only) you compose in Go inside your infra repository. It is the developer-facing, compile-time way to load the authoritative aggregate — distinct from the Mongo read side, which is the end-user-facing query facade over the eventually-consistent projection. Your repository interface stays in business vocabulary (FindByID, FindByEmail, …); the engine is how the infra implementation fulfills it. 

// Primary-key shortcut (assumes the ID↔id convention):
u, err := repo.FindOne(ctx, criteria.ByID(id))

// Any alternate key — no hand-rolled SQL:
u, err := repo.FindOne(ctx, criteria.Where(criteria.Eq("Email", email)))

// Boolean composition + order + limit; FindAll returns []*User (children batched):
users, err := repo.FindAll(ctx, criteria.Where(criteria.And(
    criteria.Eq("TenantID", t),
    criteria.Or(criteria.Eq("Status", "active"), criteria.ILike("Name", "bob%")),
    criteria.IsNull("DeletedReason"),
)).OrderByDesc("CreatedAt").Limit(50))

// Archived scope (soft-delete gate) lives on the Query, not in the predicate:
archived, err := repo.FindOne(ctx, criteria.ByID(id).OnlyArchived())

Operators: Eq/Ne/In/Nin/Gt/Gte/Lt/Lte/Like/ILike/IsNull/NotNull, combinators And/Or/Not (nestable), and sugar Contains/StartsWith/EndsWith (case-insensitive, wildcards escaped) + Between. Field names are your Go field names ("Email"), resolved to columns by the same TableSchema auto-scan uses (declared in the schema via Field("Email", "email")). Values are always parameterized; a domain.ID value is unwrapped automatically. FindByID / FindArchivedByID (promoted by BaseAggregateRepository) are themselves thin wrappers over FindOne(criteria.ByID(id)) — one SQL-building path for every load.

Automatic scan mode (recommended default)

No scanner passed. The loader builds SELECT col1, col2, ... FROM table WHERE id=$1 AND deleted_at IS NULL from the columns declared in the TableSchema and writes each into its struct field by index via row.Scan. Only declared fields are selected — an undeclared exported field is simply absent from the schema, and the private fields of the embedded AggregateRoot / BaseEntity are never declared, so neither leaks into SQL. 

// User with 4 exported domain fields
type User struct {
    domain.AggregateRoot      // embed; private fields, invisible to the engine
    Name  string
    Email string
    Username string
    Phone *string             // nullable: pointer maps directly to NULL
}

// Canonical Repository: BaseAggregateRepository bundles loader + writes.
// FindByID / FindArchivedByID promoted via embed — zero manual wrappers.
type UserRepository struct {
    fwinfra.BaseAggregateRepository[*User]
}

func NewUserRepository(pg *fwinfra.Postgres) *UserRepository {
    r := &UserRepository{
        BaseAggregateRepository: fwinfra.NewBaseAggregateRepository[*User](
            pg, func() *User { return &User{} },
        ),
    }
    // Children declared on the schema via .Child(...); WithSchema threads it
    // into the write binding AND the read loader (auto-scan).
    r.WithSchema(UserSchema())
    return r
}

The loader generates: 

-- Root (FindOne(criteria.ByID(id)) — id read back; criteria drives the WHERE)
SELECT id, name, email, username, phone FROM users
 WHERE id = $1 AND deleted_at IS NULL;

-- Per child declared via .Child(...) on the schema (FindAll batches with fk IN ($1,$2,...))
SELECT user_id, id, label, street, number, complement, neighborhood, city, state, zip_code, country
  FROM addresses
 WHERE user_id = $1 AND deleted_at IS NULL;

Column ↔ field mapping

Names are not inferred — the auto-scan resolves each column to its Go field through the repository's TableSchema (the same map that drives the write path). At boot the schema records, per declared field, a column → struct-field-index plan (TableSchema.scanPlan); the loader builds the SELECT from exactly those columns and scans each row straight into the matched field by index. There is no pgx name normalization and no convention — see TableSchema (PG + views). 

func UserSchema() *fwinfra.TableSchema {
    return fwinfra.NewTableSchema[*User]("users").
        PK("id").
        Field("Name", "name").
        Field("DisplayName", "display_name").  // any Go field ↔ any column
        Field("Email", "mail").                // a rename lives only here
        SoftDelete("deleted_at").
        CreatedAt("created_at").
        UpdatedAt("updated_at")
}

To map a Go field to a differently-named column, declare it explicitly with Field("Go", "column") — a typo on either side is a boot panic, not a silent mismatch. To keep a field out of persistence, simply do not declare it in the schema: an undeclared exported field is runtime-only by construction (never written, scanned, or audited) — no db:"-" tag, the domain stays zero IO with no tag at all.

Nullables

NULL-able columns map to pointer types in the domain (*string, *int64, *time.Time). pgx writes NULL when the pointer is nil; reads NULL as nil on auto-scan. Recommended boundary convention: empty JSON input becomes nil via a local helper (e.g., NilIfEmpty(s string) *string in your service's commands package).

Performance

The engine caches the column → field index mapping by reflect.Type in sync.Map. The first call pays the reflection (~µs); subsequent calls do direct lookup and row.Scan writes into the field address with no intermediate allocations. Benchmark against the manual scanner (8 columns, 1 row, Apple M4 Max):

Variantns/opB/opallocs/op
Manual scanner116478138026
Auto-scan (cached reflection)11509491611

Auto-scan came out slightly faster and allocates less memory than the manual scanner, because the manual path allocates temporary pointers (var phone *string; var deletedAt *time.Time) that auto-scan avoids — it writes directly into the fields.

Manual mode (escape hatch)

When the query needs something the engine does not generate — JOIN with another table, CASE/COALESCE, aggregate SQL expressions, lookup by non-id field, external materialized view — you provide the scan function via WithRootScanner and/or WithChildScanner. The loader keeps handling children dispatch and AggregateConstructor; only the decoding is up to you. 

// Manual mode runs SELECT * — scan id first (the framework no longer injects
// it on the criteria path) and SetID, then decode the rest however you like.
r.loader = fwinfra.NewAggregateLoader[*User](pg, factory).
    WithRootScanner(func(row pgx.Row) (*User, error) {
        u := &User{}
        var id, firstName, lastName string
        if err := row.Scan(&id, &firstName, &lastName /* …, &u.Email, etc */); err != nil {
            return nil, err
        }
        u.SetID(domain.NewID(id)) // REQUIRED: FindOne/FindAll recover the id via GetID()
        u.Name = firstName + " " + lastName
        return u, nil
    })
// Address keeps auto: it is declared on the schema via .Child(...) and the
// schema is threaded with r.WithSchema(UserSchema()); WithRootScanner overrides
// only the root decode.

Auto and manual coexist per typeName: for the same child, the manual scanner wins over auto when both are registered. The manual mode uses SELECT * (compatible with custom queries you may write).

Manual root scanner + FindOne/FindAll: the scanner must populate the entity id (scan it and call SetID). The criteria path has no input id to inject (unlike the old by-id load), so the framework recovers the id via GetID() after your scanner runs — an empty id is a configuration error. Auto-scan reads the id back automatically; only the manual path carries this requirement.

Errors and edge cases

  • Root not found → *DomainError with RecordNotFoundNotification (→ 404 HTTP via Semantic mapping).
  • More than one match in FindOne → error ("expected one"): the contract is a single match; use FindAll or a more specific criterion.
  • Aggregate without children — declare no .Child(...) on the schema (and no WithChildScanner) and the load only does SELECT root.
  • Entity without exported domain fields in auto mode: FindOne/FindAll return a descriptive error suggesting WithRootScanner (typically a bug — an entity with no data at all is rare).
  • Type registered in WithChildScanner without an entry in AggregateChildren() — silently ignored (compatible with evolving aggregate).
Result: with ~40 lines of code per entity you get typed validation and i18n, atomic transaction with outbox, structured audit, event publication, standardized HTTP response and automatic error translation per AppContext.Language(), and FindByID comes for free via auto-scan.
