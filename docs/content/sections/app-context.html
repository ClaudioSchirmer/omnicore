AppContext middleware

bootstrap.Run automatically registers fwweb.AppContextMiddleware() as a default middleware. Per request, it populates *configuration.AppContext with:

  • ID — UUID from the X-Request-ID header (or a new one if missing/invalid). Always returned in the response for correlation.
  • Language — prefix match of Accept-Language against the configuration.Language enum (built-ins: pt→LangPTBR, en→LangENG, es→LangES, fr→LangFR, de→LangDE, it→LangIT, nl→LangNL). Default LangENG — header absent or naming a language the framework does not ship a catalog for both resolve to English.
  • Identity — the authenticated principal of the request (*configuration.Identity). Populated by the auth middleware after a successful JWT validation; nil when the route is public, auth.mode=disabled, or the middleware has not yet run. See microservice.<profile>.yaml for how to wire the auth: block.

In any Fiber handler:

func myHandler(c fiber.Ctx) error {
    ctx := fwweb.AppContext(c)  // *configuration.AppContext
    // ctx.ID(), ctx.Language()
    if id := ctx.Identity(); id != nil {
        // id.Subject, id.Issuer, id.ExpiresAt, id.Claims (map[string]any)
    }
}

configuration.Identity carries the standard JWT claims Subject (sub), Issuer (iss), ExpiresAt (exp), plus a raw Claims map[string]any for custom claims (roles, email, tenant, …) — the framework does not opine on which custom claims a service expects.

Where AppContext flows below the web boundary

Identity() is read in Fiber handlers, but the request *AppContext also travels one layer deeper — into the application layer — through exactly two symmetric seams. Both exist for the same purpose: translate a claim into a business-named value and inject it where it is needed. The web boundary stays dumb (Request.ToCommand() / ToQuery(criteria) carry no ctx), the domain stays IO-free, and infra never sees the JWT — identity translation lives in exactly these two methods and nowhere else.

SideSeamInjects the claim into
Write Command.ToEntity(ctx) / ApplyTo(ctx, t) / ApplyPartiallyTo(ctx, t) a field on the entity — either a runtime-only field (not declared in the TableSchema, feeds BuildRules and is never persisted) or a persisted field (declared via TableSchema.Field("OwnerID","owner_id") → a real column)
Read Query.ToCriteria(ctx) the ReadCriteria.Filter the handler forwards to ViewReader.ReadPage / ReadByID

The two are mirror images: the Command (or Query) is the only layer below the web boundary that may consume *AppContext. The write-side and read-side mechanics are detailed under Auto command handlers (and CommandHandler for the manual flow) and QueryHandler · CQRS.

Stamp a claim on insert, filter by it on read

When the write-side field is persisted (declared in the TableSchema), the two seams compose into a canonical cycle: ToEntity(ctx) stamps the claim onto a real column at insert time, and ToCriteria(ctx) later filters rows by that same column. This is the general pattern for any claim that must become a persistent scope — owner-by-subject, tenant isolation, region, etc. tenant_id / owner_id are the canonical instances; the full write-stamp + read-filter + match-invariant cycle (with the tenant gate and TenantMismatchNotification) lives under Authorization, Layer 3. 

// WRITE — stamp the JWT subject onto a PERSISTED column (declared via TableSchema.Field("OwnerID","owner_id") → real column owner_id).
func (c InsertDocumentCommand) ToEntity(ctx *configuration.AppContext) (*Document, error) {
    d := &Document{Title: c.Title /* ... */}
    if id := ctx.Identity(); id != nil {
        d.OwnerID = id.Subject          // claim → persisted field; the INSERT writes column owner_id
    }
    return d, nil
}

// READ — filter by that same column from the same claim.
func (q FindDocumentsQuery) ToCriteria(ctx *configuration.AppContext) (fwqueries.ReadCriteria, error) {
    crit := q.Criteria
    if id := ctx.Identity(); id != nil {
        if crit.Filter == nil { crit.Filter = map[string]any{} }
        crit.Filter["owner_id"] = id.Subject   // overlay → only the caller's own documents return
    }
    return crit, nil
}

Contrast with the runtime-only case: a field not declared in the TableSchema (e.g. RequestingPrincipalEmail populated by ApplyTo(ctx, t) to feed an owner-check in BuildRules) never reaches a column, so it cannot be filtered on later. Persist the claim only when a later read must scope by it.

Extra request-scoped state beyond Identity (e.g., feature flags resolved per request) goes in middleware AFTER the default, via ctx.Set(key, val).
